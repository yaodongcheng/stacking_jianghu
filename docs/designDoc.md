一、游戏概述
1.1 一句话概括
玩家因故家破人亡流落到一个小镇，初始一贫如洗，需要在小镇扎根，解决NPC的困难赢得支持，壮大势力，最终对抗仇敌。
1.2 核心玩法定义
AI小镇的核心卖点是AI驱动的动态叙事——NPC有自己的人设、事件由AI生成、剧情不重复。一个自然的想法是：既然AI是核心卖点，我们应该全力做AI叙事，让故事本身成为玩法。
这意味着两条路线：
路线做法代表产品A. 纯AI叙事流玩家和NPC自由对话，AI实时生成剧情走向，没有传统数值体系，体验类似互动小说/TRPGAI Dungeon、Character.AI角色扮演、部分AI视觉小说B. 数值经营 + AI叙事先有一套脱离AI也能玩的模拟经营/生存数值循环，AI在此之上让事件更丰富、叙事更自然我们选择的方向
我们选择路线B。以下是原因。
问题1：纯AI叙事没有数值锚点，选择就没有重量
纯叙事流中，玩家做一个选择——比如"帮老赵还是不帮"——后果是什么？是AI生成的一段文字告诉你"老赵很感激"或"老赵很失望"。
问题在于：玩家读完就忘了。因为这个"感激"或"失望"不会真正影响接下来的游戏体验。NPC说他恨你，但你下次还是能跟他对话，他也不会真的拿刀来砍你、真的让你买不到食物、真的让你在冬天冻死。
冰汽时代的选项之所以令人痛苦，不是因为文案写得好，而是因为选完之后你的煤炭真的少了500，你的人真的死了200个，你接下来的10分钟游戏体验真的变难了。
结论：没有数值系统承接后果的选项，只是阅读体验，不是游戏体验。
问题2：纯AI叙事流缺乏长期留存的钩子
互动叙事类产品有一个共同困境：玩家在新鲜感消退后没有理由继续玩。
AI Dungeon的用户数据、Character.AI的留存曲线都印证了这一点——玩家初次体验时惊叹"AI好厉害"，但一周后就觉得"也就那样"，因为没有进度感、没有成长感、没有"我还差一点就能达成某个目标"的牵引力。
模拟经营天然解决这个问题：
我的铜币从10攒到了500——成长感
我还差3个NPC就能凑齐对抗仇敌的团队——目标感
我这周的食物储备够了但是冬天快来了衣服还没着落——紧迫感
结论：数值系统提供持续的目标牵引力，是长期留存的基础设施。
因此最终的框架是
模拟经营 + AI驱动叙事 + 社交策略
模拟经营层（底层）：脱离AI也能独立运转的生存/经济/社交数值博弈
AI叙事层（上层）：AI基于当前世界状态动态生成事件，让叙事与机制统一
社交策略层（贯穿）：NPC关系网是核心资产，玩家通过选择经营这张网

1.3 参考作品
参考作品参考维度潜水员戴夫个体视角的日循环节奏：获取信息→准备资源→消耗验证冰汽时代2选项设计：多资源维度拉扯，没有全赢选项王权（Reigns）单次决策影响多个维度的滑动条，数值归零即死亡中国式家长NPC人生节点的"养成→爆发"叙事结构
举例说明一个冰汽时代2的选项设计，希望让玩家达成这样的纠结效果：
1、玩家刚进入游戏，目标是带领百姓们在寒冬中活下去。
2、系统会反复教育玩家以下事实：煤炭很重要，没有煤炭大家都会冻死；劳动力也很重要，没有劳动力就没人挖煤。社会舆论也很重要，如果做事情不让Npc满意就会降低信任值，信任值为0就会被赶下台。
3、经过多次游戏内部循环，玩家会认可上述规则，这是一个资源权衡游戏。
4、这时候刷新一个事件：煤矿内部着火，但是里面还有一些工人没出来。
选项A：封死煤矿，这样之后煤矿还有继续复用的可能。
后果：劳动力-200，之后可能会出现事件人们表达对执政官冷血的不满。
选项B：尽量把人救出来，但是煤矿以后就不能用了。
后果：劳动力-10，但是煤矿资源储备-1000，人们欢呼雀跃，但是你之后会面临资源不够用的危机，一样会引来玩家不满。
选项C：忽视不管（可能是最恶劣的后果）
这里之所以令人纠结，就是因为玩家非常认可劳动力、煤炭以及信任度这三个数值。

2.1 社会系统的三层目标结构

本游戏的核心挑战不是"打败一个Boss"或"通关一个关卡"，而是面对"一群人"组成的动态社会系统。这种挑战需要与传统游戏同构但操作对象不同的三层目标结构：

```
三种挑战的目标结构对照：

【Boss战】                    【关卡探索】                  【一群人（本游戏）】
Micro：预判出招，闪避/反击    Micro：发现线索/路径          Micro：观察→策略→行动→反馈
Meso：削血到阶段转换          Meso：打开区域/解锁机关       Meso：改变关键NPC的立场/行为
Macro：击杀Boss              Macro：完成探索               Macro：让社会系统到达目标状态
```

**Macro（终极目标）：让社会系统到达目标状态**
- 对应主线：积累足够的盟友、资源和势力，在仇敌到来时有能力对抗
- 胜利条件不是"消灭"或"通过"，而是"改变状态"——改变人际关系网络的拓扑结构，改变关键人物的立场、态度、行为
- 玩家在游戏全程中，逐步将小镇的社会网络从"各自为政/对你冷漠"改造为"以你为核心的同盟网络"

**Meso（阶段目标）：改变关键NPC的立场或行为**
- 对应NPC人生节点：每个NPC人生节点就是一次"阶段转换"
- 通过介入NPC的两难抉择，推动关键人物的立场发生不可逆的变化
- 类似Boss战的"阶段转换"——张铁匠从"中立观望"变为"坚定盟友"，就是一次阶段转换

**Micro（即时操作）：观察→策略→行动→反馈 循环**
- 这是当前文档最缺失的一层，也是"游戏性"成立的基础
- 每次社交互动的微观循环：
  1. **观察**：读取NPC当前的状态信号（表情、行为、位置、与谁在一起）
  2. **策略选择**：基于观察，决定用什么手段（诚实/欺骗/施压/示弱/借力）、在什么时机、对谁
  3. **执行有成本的行动**：每个行动都消耗资源（时间、金钱、人情、体力），不是免费试探
  4. **获得反馈**：NPC的行为发生可观察的变化（不只是文字回复），社会网络状态更新

关键设计原则：
- 玩家在任何一个时刻都必须知道自己在"朝着什么前进"——这是游戏性成立的基础
- 微观操作的"观察-判断-执行-反馈"循环与Boss战的"预判-反应"循环在结构上同构
- 上手层：任何人都能和NPC交谈、完成简单请求、感知到"有事在发生"
- 精通层：理解NPC之间的隐性关系网络、理解信息作为资源的价值、理解时机的重要性、理解二阶效应（帮了A，B会怎么看你？）

3.2 AI输出的收束机制

**核心架构规则：AI的每次输出 = 表现文本 + 系统状态变更指令**

AI不是一个自由发挥的文本生成器，而是一个"有表现力的接口"，背后是严格运作的游戏系统。每次AI生成内容（无论是NPC对话、事件描述还是行为决策），都必须同时输出结构化的状态变更指令，后台系统据此更新游戏状态。

**落地方式：复用现有 StoryDirectiveExecutor**

项目已有 `story_directive_executor.py` 支持完整的指令类型（SET_AFFINITY、NPC_MOVE、SET_RELATION等）。AI输出的"状态变更"部分直接映射为 StoryDirective 指令序列。

示例：
```
AI叙事引擎输出：
  表现文本 = "张铁匠听你说完，沉默了很久，最后重重地拍了一下桌子：'好！我信你！'"
  
  对应的 StoryDirective 指令序列：
  - SET_AFFINITY(target=张铁匠, value=+20)
  - SET_RELATION(target=张铁匠, relation=盟友)
  - SET_EMOTION(target=张铁匠, emotion=激动)
  - NPC_SAY(target=张铁匠, text="我老张这条命，交给你了！")
```

这个机制确保：
- AI不会"飘走"——说了"我信你"就必须通过 SET_AFFINITY 在数值上体现为好感变化
- AI不会产生幻觉破坏游戏性——NPC不能口头承诺了什么但系统状态没变
- 所有AI输出都可以被游戏系统验证和审计
- 无需开发新的指令系统，复用已有的 StoryDirective 基础设施

3.3 AI的四条约束原则

**原则1：AI不生产游戏性，设计师生产游戏性**
- ✗ 让AI决定NPC会不会被说服 → 玩家在"破解prompt"
- ✓ 设计师定义说服条件（好感≥60 + 持有关键情报 + 某NPC已改变立场），AI决定NPC被说服时怎么表现
- AI生产的是表现力和灵活性，不是游戏规则

**原则2：AI的输出必须被系统"收束"**
- 见上述3.2的收束机制
- 确保AI是有表现力的前端，背后是严格的游戏后端

**原则3：对话不是唯一甚至不是主要交互方式**
- AI同样驱动：NPC行为决策、环境叙事生成、对玩家非对话行为的响应
- NPC能"看懂"你做了什么（夜里鬼鬼祟祟从某人家出来），而不只是"听懂"你说了什么

**原则4：涌现必须在设计空间内涌现**
- NPC行为空间有限、状态空间有限，AI的自由度在于：在有限空间内，以怎样的路径和表现力来迁移
- 有方向的涌现 ≠ 无方向的模拟（斯坦福小镇实验很酷但没人想"玩"它）

4.2 属性用途
4.2.1 生存压力
玩家每一天都面临数值自然流失的压力，必须主动行动来维持生存
三条命脉（生存线、经济线、声望线）任意一条崩溃都会导致游戏失败
4.2.2 事件选项解锁
事件选项的门槛直接读取能力属性和社交属性：
示例：
选项"以理服人"  → 门槛：智力 ≥ 25，与当事人好感 ≥ 20
选项"暴力解决"  → 门槛：力量 ≥ 30，
选项"偷偷解决"  → 门槛：敏捷 ≥ 20，
选项"花钱摆平"  → 门槛：铜币 ≥ 200

  好感 > 70   → 忠诚：可被招募为粉丝，愿意为玩家冒险

5.2 故事主线
初始，玩家流落到小镇上逃难，但是仇敌迟早会找上门来。随着游戏进程时间流逝和玩家的操作，仇敌对玩家的威胁度会逐渐上升：
威胁度 20 → 【节点1】镇上出现陌生人打听事情（信息层面）
威胁度 40 → 【节点2】仇敌的手下来镇上施压某NPC（间接冲突）
威胁度 60 → 【节点3】仇敌直接对玩家的盟友下手（正面冲突前奏）
威胁度 80 → 【节点4】仇敌亲自或派精锐来镇（最终对抗序幕）
威胁度 100 → 【终局】不可避免的决战
5.3 随机事件
玩家的游玩过程就是 解决事件 和 提升自我 中反复循环。在这个过程中玩家的能力会越来越强，粉丝团会越来越大，最终有实力直面恶人。
威胁度 < 20（平静期）：
  AI事件种子池=日常生活类（邻里纠纷、经济困难、情感问题）
  目的：让玩家熟悉镇子、建立关系、积累资源
├── 【蜜月】连续2-3天顺利事件，资源获取大于消耗
├── 【小波澜】1天出个小麻烦，考验玩家是否掌握了基础机制
└── 【暗示】1天出现一个看似无关但实则暗示仇敌存在的事件
威胁度 20~40（暗流期）：
  AI事件种子池 +=社会动荡类（有人被勒索、商路被截、流言四起）
  目的：让玩家感受到"外部势力在渗透"，这些事件表面是NPC的日常，
       但背后和仇敌势力的扩张有关联
├── 【暗流涌动】表面日常事件，但连续2-3天结果都指向同一个幕后势力
├── 【信任危机】某个你依赖的NPC突然态度转变，需要调查原因
└── 【意外收获】在压力中突然获得一个盟友或资源，缓解节奏
威胁度 40~60（风暴前）：
  AI事件种子池 +=站队抉择类（NPC被迫选边站、有人想叛变投敌）
  目的：玩家之前积累的社交关系开始被考验
├── 【站队风暴】连续事件迫使多个NPC表态，关系网剧烈重组
├── 【围城前夜】资源供给线被切断，需要紧急开辟替代方案
└── 【叛徒】一个高好感NPC被揭露/被胁迫背叛
威胁度 60+（正面对抗）：
  AI事件种子池 +=战争类（资源争夺、攻防、营救）
  目的：之前所有积累的资源、关系、能力全部进入"兑现"阶段
├── 【攻防战】资源大量消耗，盟友受伤/阵亡，每个选择都有重大代价
├── 【绝地反击】在极端劣势下出现一个高风险高回报的翻盘机会
└── 【决战】终局对抗，所有积累的关系和资源进入结算

5.4.1 AI导演监控信号

AI导演实质上是一个实时运行的"动态关卡设计器"，它持续监控以下玩家状态信号，据此调整叙事节奏：

| 监控维度 | 具体指标 | 数据来源 | 说明 |
|---------|---------|---------|------|
| 目标进度 | 主线威胁度、当前NPC人生节点阶段 | 威胁度系统、StoryDirector | 玩家离终局有多远 |
| 资源压力 | HP、饱食度、寒冷值、铜钱 | 角色属性系统 | 玩家当前的生存余量 |
| 事件密度 | 最近N天内触发的事件数量、事件间隔天数 | 事件历史日志 | 玩家经历了多少"大事" |
| 社交密度 | 玩家最近的NPC交互频次、好感变化幅度 | 社交关系系统 | 玩家的社交活跃度 |
| 情绪轨迹 | 最近5天的体验标签序列（顺利/纠结/挫败） | 情绪日志 | 连续挫败需要缓解 |
| 沉浸感指标 | 玩家主动闲聊频率、主动探索行为（如查看告示板、训练、交易） | 行为日志 | 玩家是否在主动参与世界 |

基于这些信号的综合评估（即"承压指数"），导演动态调整：
- **事件触发时机**：资源压力高+事件密度高 → 延后下一个事件，给喘息空间
- **冲突升降级**：连续顺利 → 加压升级；连续挫败 → 缓和降级
- **节奏留白**：事件密度过高时，主动插入"平静日"，让玩家有时间经营和准备
- **信息投放**：沉浸感低时，增加NPC主动搭话、告示板更新等引导；沉浸感高时，减少干预让玩家自由探索

5.4.2 导演干预的分寸感

导演干预的核心难题在于分寸——太强，玩家会觉得被"推着走"，丧失自主感；太弱，叙事可能失控，玩家不知道该做什么。

设计原则：
- 导演只调节**节奏和强度**，不决定**具体内容和结果**——"什么时候来事"由导演决定，"来什么事、怎么选"由AI叙事引擎和玩家决定
- 导演的调节对玩家**不可见**——玩家感受到的是"世界自然运转"，而非"被安排"
- **保护规则优先于施压冲动**：连续施压不超过3天，连续挫败后必须给正反馈机会
- 导演永远不会阻止玩家的自由行动，只会调整NPC和事件的反应强度
- 当玩家主动制造冲突（如挑衅NPC、偷窃）时，导演不干预后果——玩家选择的后果应如实兑现

导演不负责的事情：
- 不生成具体的对话内容（由AI叙事引擎负责）
- 不控制NPC的具体行为（由NPC行为系统/需求金字塔负责）
- 不决定事件的结局（由玩家选择+数值系统决定）

说节奏之前，先看看参考的对象：《潜水员戴夫》的玩法是一个优秀的基于个体视角的模拟经营框架，steam96%好评。

我们先来看潜水员戴夫是怎么设计不同天之间的游戏节奏的：
参考潜水员戴夫，我们可以这样设计事件游玩节奏
潜水员戴夫AI小镇来到寿司店打工上午：查看状态、获取信息夜晚触发事件，引导玩家潜水夜晚：事件触发，出现选择去潜水自由探索、搜集资源下午：工作赚钱、训练属性、探索小镇用资源卖寿司/解决事件夜晚：用资源应对事件选项（门槛/消耗）从邮件知道后面需要什么上午：NPC的话、公告栏、事件伏笔告诉你需要什么

|------|------|----------|---------|
| 子时 | 23:00-01:00 | 深夜 | 暗杀、潜入、夜间事件 |

| 寅时 | 03:00-05:00 | 黎明前 | NPC开始准备日常 |
| 卯时 | 05:00-07:00 | 清晨 | 势力任务发布、日常开始 |
| 辰时 | 07:00-09:00 | 早晨 | 情报委托触发、告示板更新 |
| 巳时 | 09:00-11:00 | 上午 | 社交活动、商业交易 |
| 午时 | 11:00-13:00 | 正午 | 事件高发期 |
| 未时 | 13:00-15:00 | 下午 | 自由行动、任务推进 |
| 申时 | 15:00-17:00 | 傍晚 | 事件触发、冲突爆发 |
| 酉时 | 17:00-19:00 | 黄昏 | 夜间活动准备 |
| 戌时 | 19:00-21:00 | 晚上 | 娱乐事件、秘密活动 |
| 亥时 | 21:00-23:00 | 入夜 | 势力活动、夜间任务 |

- 不再是"上午/下午/夜晚"三段式，而是连续的时间流逝
- 玩家可以随时做任何事，行动消耗时间
- 不同时辰有不同的事件触发概率和NPC活动规律
- 时间控制：正常速度/加速（休息/等待）/暂停（菜单/对话）

5.6 事件层次与线索系统

**核心循环：信息获取 → 资源准备 → 消耗验证**

为了解决"事件间隙无焦点"问题，引入**线索系统**作为连接事件与日常经营的桥梁：

```
┌─────────────────────────────────────────────────────────────┐
│                    玩家日常循环                               │
├─────────────────────────────────────────────────────────────┤
│                                                              │
│  【信息获取阶段】辰时-巳时（07:00-11:00）                      │
│  ├── 查看江湖告示板（公开情报、委托任务）                      │
│  ├── 与NPC闲聊（获取线索碎片）                                │
│  └── 接收情报委托（主动调查任务）                             │
│       ↓                                                      │
│  【资源准备阶段】午时-未时（11:00-15:00）                      │
│  ├── 根据线索提示，针对性提升能力                             │
│  │   例：线索提示"可能需要武力介入"→去训练力量               │
│  ├── 攒钱、收集道具、维护关系                                 │
│  └── 完成情报委托，获取完整情报                               │
│       ↓                                                      │
│  【消耗验证阶段】申时-戌时（15:00-21:00）                      │
│  ├── 事件触发（起承转合各幕）                                 │
│  ├── 用准备好的资源应对选项门槛/消耗                          │
│  └── 选择后果影响NPC命运和玩家关系网                          │
│                                                              │
└─────────────────────────────────────────────────────────────┘
```

**事件层次结构**：

| 层次 | 定义 | 时间跨度 | 玩家角色 |
|-----|------|---------|---------|
| **Npc命运线** | NPC在小镇经历的完整命运轨迹 | 游戏全程 | 见证者/推动者 |
| **Npc人生节点** | NPC遇到的两难选择，需经历起承转合4幕 | 2-4天 | 关键影响者 |
| **起承转合幕** | 人生节点的具体阶段，每幕1个事件 | 1天 | 选择推动者 |
| **线索任务** | 幕前准备，收集信息、提升能力 | 幕前任意时间 | 主动准备者 |

**起承转合与线索的对应关系**：

| 阶段 | 核心冲突 | 线索作用 | 选项特点 |
|-----|---------|---------|---------|
| **起(EMERGE)** | 问题初现 | 预告"即将发生什么" | 3选项，试探性介入，成本低 |
| **承(ESCALATE)** | 矛盾升级 | 提示"需要准备什么" | 3选项，必须站队，有门槛 |
| **转(CLIMAX)** | 关键抉择 | 揭示"真相是什么" | 2选项，二选一，代价最高 |
| **合(SETTLE)** | 后果兑现 | 记录"发生了什么" | 2-3选项，善后处理 |

**关键设计原则**：

1. **每幕前必有线索**：AI导演在生成下一幕事件前，先生成线索任务
2. **线索即准备指引**：每条线索都暗示玩家应该提升什么能力/准备什么资源
3. **准备有回报**：根据线索做准备的玩家，在事件中获得更好选项或降低成本
4. **不准备也能玩**：没有准备的玩家仍能推进，但选择受限或代价更高

**选项设计结构**：

```
每个选项包含：
├── 文本描述（15-20字，[手段]具体做法）
├── 门槛（属性/道具/关系要求）
├── 消耗（付出代价）
├── 收益（获得回报）
├── 后果预览（即时反应+长远影响）
└── 张力变化（影响局势压力）
```

**CLIMAX阶段的特殊设计**：

- 基础2选项：desire vs misgiving（两难抉择）
- 解锁第3选项：通过前置准备（收集足够线索/与关键NPC关系好/拥有特定道具）
- 第3选项特点：高成本但可能"两全其美"，奖励有准备的玩家

**SETTLE阶段的设计原则**：

- 不能"撤销"转的选择，只能"面对"它
- 根据"转"的选择结果，提供不同的善后路径
- 确保重大选择有长期影响，不能被完全修复

看到这里，会发现核心问题在于，玩家得对游戏内的数值变动有强烈的感触，整个游戏循环才能成立。线索系统正是连接"日常经营"与"事件选择"的关键桥梁，让玩家知道"该准备什么"。

5.6.1 手段光谱与成本矩阵

事件选项不仅有具体的门槛和消耗，其背后的"手段类型"本身也有系统性的长期成本。玩家选择的不只是"这次怎么做"，而是"我是一个怎样的人"——不同手段策略在四个维度上各有代价，确保没有全优策略。

**落地方式：通过事件选项标签 + 现有说服系统实现**

手段类型不是一个独立的新系统，而是**事件选项的标签维度**。每个事件选项在生成时会带有手段标签，系统据此计算成本和后果。与现有的 `persuasion_system.py`（说服系统）和 `npc_personality.py`（7维性格）配合使用。

**玩家可用的社交手段光谱**：

| 手段类型 | 定义 | 适用场景 |
|---------|------|---------|
| 诚实 | 如实表达意图，坦诚相待 | 建立长期信任、争取重情NPC |
| 欺骗 | 编造信息、隐瞒真相 | 短期操控、绕过门槛 |
| 施压 | 利用权力、威胁、把柄 | 对付怯懦或有弱点的NPC |
| 示弱 | 示弱求助、博取同情 | 争取利他型NPC、降低戒心 |
| 借力 | 利用第三方关系或势力施加影响 | 间接影响无法直接接触的NPC |
| 利益交换 | 用资源/人情换取配合 | 对付利己型NPC、快速达成目标 |
| 情感投入 | 长期陪伴、关心、帮助 | 建立忠诚关系、争取重情NPC |

**无最优解的保证：成本-副作用矩阵**

|  | 诚实 | 欺骗 | 施压 | 示弱 | 借力 | 利益交换 | 情感投入 |
|--|------|------|------|------|------|---------|---------|
| 短期效率 | 中 | 高 | 高 | 中 | 高 | 高 | 低 |
| 被识破/反噬风险 | 无 | 高 | 中 | 低 | 中 | 无 | 无 |
| 长期社会资本 | 高 | 负 | 负 | 中 | 中 | 中 | 高 |
| 时间消耗 | 中 | 低 | 低 | 中 | 中 | 中 | 极高 |
| 对NPC性格依赖 | 低 | 低 | 高 | 高 | 中 | 中 | 高 |

→ **没有任何一列全是绿色。每种策略都有代价。**

**手段与NPC性格的交互**（对接 `npc_personality.py` 7维性格）：
- 对暴躁（性情=暴躁）NPC施压 → 可能激怒反噬；对怯懦（胆量=怯懦）NPC施压 → 高效但损社会资本
- 对重情（情义=重情）NPC欺骗 → 一旦识破好感暴跌且不可修复；对薄情NPC情感投入 → 浪费时间
- 对利己（主义=利己）NPC诚实 → 效率低；利益交换更有效但不建立忠诚
- 借力的效果取决于"借谁的力"——借强者的力风险低但欠人情，借弱者的力可能适得其反

**手段混用与长期后果**（复用 `rumor_system.py` 谣言系统）：
- 玩家的手段选择会被系统记录为"行为标签"（如：偏武力、善计谋、重情义、不择手段）
- 行为标签通过谣言系统在NPC之间传播——"这个人说话从不骗人"vs"这个人什么都敢做"会在镇上形成口碑
- 行为标签影响NPC对玩家的预期——一个"不择手段"的玩家，NPC会提防他的诚实

5.8.2 感知过滤器

NPC在生成对话或决策行为前，会从世界事实库中查询信息，但查询结果需要经过**感知过滤器**——判断这个NPC是否有合理的途径知道这件事。

核心原则：**真实感不是来自NPC无所不知，而是来自他们"知道该知道的，不知道不该知道的"。**

| 感知途径 | 判定条件 | 信息质量 | 示例 |
|---------|---------|---------|------|
| 亲眼所见 | NPC在事件发生时处于同一地点 | 完全准确，细节丰富 | 张铁匠亲眼看到打手砸门，能描述人数、长相、说了什么 |
| 间接听闻 | NPC与知情者有社交关系（好感≥10），且近期（2天内）有过交流 | 基本事实准确，细节可能模糊或有偏差 | 李大婶听邻居说起赵掌柜被骚扰，知道"有人闹事"但不清楚具体经过 |
| 逻辑推断 | NPC智力≥30，且观察到相关结果或线索 | 推断可能正确也可能错误 | 药铺老板注意到张铁匠频繁来问药价，推断其家人病重（正确推断） |
| 公共知识 | 事件涟漪传播范围超过阈值（≥5个NPC知道） | 基本事实准确，动机和细节不清 | 全镇人都知道来了一群外地人，但不知道他们的目的 |

感知过滤的应用场景：
```
场景：玩家夜间暗中调查了青龙帮

NPC感知结果：
├── 张铁匠（亲眼所见：不适用，不在场）
│   → 不知道玩家去调查了
├── 夜间巡逻的王捕头（亲眼所见：看到玩家在码头附近徘徊）
│   → 知道玩家夜间行踪可疑，但不知道目的
├── 李大婶（间接听闻：第二天王捕头跟她提了一嘴）
│   → 知道"有人说你昨晚在码头那边晃"，细节模糊
├── 赵掌柜（无感知途径）
│   → 完全不知道
└── 青龙帮成员（逻辑推断：发现有人翻过他们的东西）
    → 知道"有人来查过"，但不确定是谁（除非有其他线索）
```

感知过滤与已有系统的关系：
- **与涟漪系统的配合**：涟漪系统负责"事件传播给了谁"（传播范围），感知过滤负责"NPC知道多少细节"（信息深度）。两者配合使用——涟漪系统输出受影响的NPC列表和态度变化，感知过滤器决定每个NPC在对话中能说出什么
- **与NPC行为系统的配合**：NPC的需求金字塔决定"想做什么"，感知过滤决定"基于什么信息做决策"。一个不知道外来威胁的NPC不会因此改变行为；知道了的NPC才会寻求保护
- **与AI叙事引擎的配合**：生成NPC对话时，将感知过滤后的信息注入LLM上下文，确保NPC不会说出自己不该知道的信息

6.1 NPC行为反馈的可观察化设计

反馈是游戏性成立的关键环节——玩家必须能"看到"自己的行动产生了什么效果。在Boss战中，反馈是直观的：血条下降、Boss阶段转换动画、受伤屏幕变红。在社会系统中，反馈同样必须是可观察的，而且**行为变化比数字飘字更重要**。

**NPC行为反馈的三层映射**（对照Boss战）：

| Boss战的反馈 | 社会系统的反馈 | 说明 |
|-------------|--------------|------|
| ① 血条变化 | ① NPC可观察的行为变化 | 最核心的反馈层 |
| ② Boss阶段转换动画 | ② 系统层面的状态指示 | 帮助玩家追踪进展 |
| ③ 受伤 = 明确惩罚 | ③ 失败后果具体、可感知 | 通常非Game Over |

**① NPC可观察的行为变化**（按好感区间）：

通过已有的NPC AI行为系统（`ai_system.py` + `job_behaviors/`）和原子动作队列（`atomic_actions.py`）实现。

| 好感区间 | NPC主动行为 | NPC被动反应 | 卡牌视觉表现 |
|---------|------------|------------|-------------|
| >70 忠诚 | 主动靠近玩家卡牌、触发搭话气泡 | 堆叠交互时给折扣、立即答应请求 | NPC卡牌边框发光（忠诚色）、头顶显示态度标记 |
| 30~70 友好 | 偶尔弹出打招呼气泡 | 交易正常、请求帮忙有条件答应 | NPC卡牌边框正常 |
| 0~30 中立 | 无主动行为 | 简短回应 | NPC卡牌边框正常 |
| -50~0 冷淡 | 主动远离玩家卡牌 | 拒绝请求、交易抬价 | NPC卡牌边框变暗 |
| <-50 敌对 | 主动接近并触发冲突事件 | 公开指责、拒绝一切互动 | NPC卡牌边框发红、头顶显示敌对标记 |

**② 系统层面的状态指示**：
- 命运图谱（已有 `fate_graph_ui.py`）：玩家可查看NPC之间的关系连线和态度变化
- NPC详情面板（已有 `npc_detail_panel.py`）：查看NPC的态度、性格、需求状态
- 新闻面板（已有 `live_news_panel.py`）：事件结果和社会动态的文字反馈
- 事件通知（已有 `event_notification.py`）：右侧弹出关键事件的即时通知

**③ 失败后果的设计**：
- 惹恼关键NPC → 某些事件选项被封（门槛不满足），但需要绕路，不是死局
- 信息泄露 → 通过谣言系统（`rumor_system.py`）传播，NPC行为模式改变
- 社会声誉受损 → 通过涟漪传播全镇NPC态度下调，需要时间修复
- 最严重：连续决策失误导致社会系统进入不可逆的坏结局锁定

**NPC互动的旁观效应**：

复用已有的围观AI（`spectate_ai.py`）和视觉感知系统：
- NPC在视觉感知范围内"看到"其他NPC或玩家的行为时，会产生态度变化
- 通过新闻面板（`live_news_panel.py`）向玩家呈现"镇上发生了什么"的信息
- NPC之间的互动结果以文字快照（`live_snapshot_panel.py`）形式让玩家感知

**核心原则：成功不是NPC说了"谢谢"，而是NPC的行为、态度、社会网络拓扑发生了你预期方向的变化。**

八、目前Demo不足分析

Demo已完成内容：
单个Npc起承转合
简单的Npc行为
基础的Npc、资源、建筑、道具定义，
基础的卡牌堆叠功能，配表就可以生成几千种不同的配方，比如 Npc+树木=木材
问题 1：数值无感（根因）
玩家得对游戏内的数值变动有强烈的感触，整个游戏循环才能成立。
目前状态属性、能力属性、财富、社交关系定义都有了，但它们没有形成"不满足就会死"的压力闭环。冰汽时代之所以选项痛苦，是因为煤炭=0→全城冻死、劳动力=0→没人干活、信任=0→下台。你的小镇目前缺少等价的生存压力源。
玩家即使不触发事件，也必须每天想办法吃饭、赚钱、找地方住，这就是"脱离AI也能玩"的底层经营循环。
数值变化必须有即时的、夸张的UI反馈：
饱食度低于30%：屏幕边缘出现黑影，角色走路变慢
铜币不足时查看事件选项：被锁选项显示红色大锁+需要的铜币数
好感变化：NPC头顶弹出 ❤️+20 或 💔-40 的飘字，且NPC的表情/对话态度立刻变化
问题 2：事件间"真空期"
小镇在事件结束后，在下一个事件开始之前，玩家不知道下一步该攒什么、防什么。失去目标焦点，我应该去赚钱还是提升能力还是搞好人际关系？
参考潜水员戴夫的白天/夜晚天然制造了"信息获取→资源准备→消耗验证"的节奏。
问题 3：自由度与叙事一致性
比如牛二找玩家胡搅蛮缠，玩家完全可以找他的领导黑风大王投诉，无论黑风大王认可与否，后面这件事情都应该在剧情中体现。但是目前这一块还没有融合的很好。
优先级判断
问题1 >=  问题2 > 问题3
数值无感是地基问题，地基不稳，再好的叙事也撑不住循环。
问题2是中层框架。
问题3是上层自由度，可以在前两层稳固后再做。


九、非对话行动系统

核心理念：社交策略是游戏的核心循环，但它不能成为游戏循环本身——它必须嵌入到更大的游戏循环中。如果玩家的全部玩法就是"和NPC对话选选项"，那做出来的不是游戏，是跑团聊天室。

**落地方式：基于卡牌堆叠的行动扩展**

本游戏的核心交互范式是卡牌堆叠（拖拽卡牌触发交互）。非对话行动不需要另起一套操作系统，而是**复用卡牌堆叠配方（recipes）和NPC事件广播机制**来实现。

```
┌──────────────────────────────────────────────────────┐
│                                                      │
│                   社交策略（核心循环）                  │
│                                                      │
│         ↑ 信任建立              需要情报 ↓            │
│                                                      │
│  【卡牌堆叠·调查】                   【对话·情报】    │
│  玩家卡+地点卡=调查事件               NPC对话获取线索  │
│  玩家卡+物证卡=获得情报               闲聊捕获碎片信息 │
│                                                      │
│         ↑ 需要物证              受制于 ↓              │
│                                                      │
│  【卡牌堆叠·行动】                   【资源管理】     │
│  物品卡+NPC卡=送礼                   时间（一天有限） │
│  玩家卡+建筑卡=训练/工作             金钱 / 物资      │
│  玩家卡+NPC卡=各类互动               人情 / 声誉      │
│                                                      │
└──────────────────────────────────────────────────────┘
```

9.1 卡牌堆叠行动类型

以下行动全部通过已有的 `recipes.csv` 配方系统实现，无需开辟新的交互模式。

**① 资源类堆叠（已有，扩展语义）**

| 配方 | 产出 | 说明 |
|------|------|------|
| 玩家 + 树木 | 木材 | 基础资源采集 |
| 玩家 + 建筑(铁匠铺) | 训练力量 | 消耗时间，能力+1~3 |
| 玩家 + 建筑(书院) | 训练智力 | 消耗时间，能力+1~3 |
| 玩家 + 建筑(集市) | 打工赚钱 | 消耗时间，铜钱+ |

**② 社交类堆叠（核心扩展）**

| 配方 | 效果 | 社交影响 |
|------|------|---------|
| 物品卡 + NPC卡 | 送礼 | 目标好感+，消耗物品，周围NPC通过视觉感知看到 |
| 玩家卡 + NPC卡 | 触发对话/事件 | 根据当前关系和上下文生成交互 |
| NPC卡 + NPC卡 | 引荐/调停 | 玩家作为中间人，消耗双方人情 |

**③ 情报类堆叠（新增配方类型）**

| 配方 | 效果 | 条件 |
|------|------|------|
| 玩家 + 建筑(酒馆) | 获取公开情报/谣言 | 消耗时间和铜钱 |
| 玩家 + 建筑(告示板) | 查看公告/委托 | 内容由AI导演动态更新 |
| 线索卡 + NPC卡 | 向NPC求证/展示证据 | 可能解锁新对话选项或改变NPC态度 |
| 线索卡 + 线索卡 | 拼合情报 | 两条碎片信息合成更完整的情报 |

9.2 NPC视觉感知与行为广播

复用已有的NPC视觉感知系统（`spectate_ai.py`）和事件广播机制：

- 玩家在某NPC附近执行卡牌堆叠行动时，该NPC通过视觉感知系统"看到"这个行为
- "看到"的行为会影响NPC态度：
  - NPC看到玩家送礼给自己的朋友 → 好感微增
  - NPC看到玩家攻击自己的朋友 → 好感暴跌
  - NPC看到玩家在帮助弱者 → 根据NPC性格（利他/利己）产生不同态度变化
- 广播范围由 `spatial_hash` 决定——只有在感知范围内的NPC才会被影响

9.3 行动的时间成本与互斥性

每个卡牌堆叠行动都消耗时间（以时辰为单位），这是"无最优解"的底层保障：
- 你去铁匠铺训练（耗时2时辰），就没时间去酒馆打听消息
- 你帮张铁匠做事（耗时1时辰），就错过了去集市赚钱的机会

**一天只有12个时辰，而你需要：吃饭、赚钱、训练、社交、准备应对事件。资源永远不够，选择永远有代价。**

9.4 与现有系统的关系
- **配方系统**（`recipe_system.py`）：所有行动通过配方定义，新增行动=新增配方条目到 `recipes.csv`
- **事件广播**（`spectate_ai.py`）：NPC视觉感知范围内的行为自动广播
- **涟漪系统**（`ripple_engine.py`）：公开行动的结果通过涟漪传播影响更多NPC
- **AI导演**（`director_system.py`）：导演监控玩家的行动模式，调整事件触发节奏
- **谣言系统**（`rumor_system.py`）：玩家的行为可能生成谣言在NPC之间传播


十、空间可读性设计

"可读性"是游戏设计的基础原则之一——玩家能不能"看懂"正在发生什么。在本游戏的卡牌堆叠范式下，可读性通过卡牌的视觉状态、空间布局和UI面板来传达。

10.1 卡牌空间布局 = 社会结构的隐喻

本游戏中NPC以卡牌形式存在于2D世界地图上（`world_map.py`），卡牌的空间位置由建筑归属和AI行为驱动。虽然不是传统的"小镇俯瞰"，但空间布局仍然传达社会信息。

**建筑区域划分**（通过 `building_defs.py` 定义）：
- NPC所属建筑反映其社会地位（官府、商铺、农田、城外）
- 玩家拖动摄像机浏览地图时，可以通过建筑分布大致读懂社会结构
- NPC的日常行为（`job_behaviors/`）驱动其在不同建筑间移动，形成可观察的规律

**卡牌视觉状态传达的信息**：

| 视觉信号 | 传达的信息 | 玩家可得出的推断 |
|---------|----------|----------------|
| NPC卡牌在哪个建筑区域 | 职业和社会地位 | 谁是重要人物、谁在底层 |
| NPC卡牌偏离日常位置 | 日常被打破 | 可能发生了什么事 |
| 多个NPC卡牌聚集在同一位置 | 有事件发生或社交活动 | 引导玩家注意 |
| NPC卡牌边框颜色变化 | 好感/态度状态 | 关系好坏一目了然 |
| NPC头顶气泡/标记 | 有话要说或状态异常 | 引导玩家交互 |

10.2 NPC卡牌位置本身是信息

NPC的日常位置遵循需求金字塔驱动的日程和职业行为（见第六章），但关键在于：**位置偏离本身就是一个信号**。

- 铁匠不在铁匠铺的建筑范围内 → 可能出事了
- 两个平时不来往的NPC卡牌出现在同一位置 → 可能在密谋什么
- 某NPC卡牌连续两天不移动 → 可能害怕什么
- 外来势力的NPC卡牌出现在镇中心 → 局势升级的信号

AI导演可以通过 NPC_MOVE 指令调整NPC位置来"不动声色地"传递信息，而不需要弹窗提示。

10.3 环境叙事

复用已有的UI面板系统传达环境信息：

- **新闻面板**（已有 `live_news_panel.py`）：公开情报、事件动态、社会变化
- **事件通知**（已有 `event_notification.py`）：右侧弹出关键事件的即时通知
- **侧边栏要务区**（已有 `sidebar.py`）：当前最紧急的事务提示
- **商店物品变化**：某种物资突然涨价或断货 → 暗示供给线出了问题（通过 `economy_system.py`）

10.4 操作可读性

玩家在任何时刻都要能判断"我现在能做什么"。

**设计原则**：
- 卡牌堆叠交互天然提供结构化的行动空间——玩家的操作就是"拖哪张卡牌放到哪张上"
- 可堆叠的组合通过配方系统（`recipe_system.py`）定义，无效堆叠给出提示
- 当前语境下的可用行动通过侧边栏要务区提示（但不直接给最优答案）
- 事件选项中不可用的选项标注原因（门槛不足、资源不够）


十一、信息战略系统

在社会系统挑战中，信息是最重要的战略资源之一。"知道什么、什么时候说、对谁说"是玩家从新手到高手的核心成长维度。

11.1 信息作为资源

信息不是免费的背景文本，而是有获取成本、有使用价值、有时效性的战略资源。

| 信息特征 | 说明 | 示例 |
|---------|------|------|
| 获取成本 | 信息需要投入时间、冒险或消耗人情才能获得 | 通过卡牌堆叠（玩家+酒馆）花费铜钱和时间获取 |
| 使用价值 | 信息可以解锁事件选项、改变NPC态度、影响局势 | 知道张铁匠女儿的下落→可在关键时刻作为筹码 |
| 时效性 | 某些信息有时间窗口，过期失效 | 青龙帮明晚的行动计划→明天之后就没用了 |
| 排他性 | 你知道而别人不知道的信息更有价值 | 你是唯一知道真相的人→可以选择告诉谁 |

11.2 信息操控——通过事件选项和对话落地

信息操控不需要独立的交互系统，而是**嵌入到现有的事件选项和NPC对话中**。

**选择性透露**（通过事件选项实现）：
- 你知道青龙帮要对张铁匠下手。下次事件触发时会出现选项：
  - 选项A：告诉张铁匠 → 好感+，但可能打草惊蛇（涟漪传播）
  - 选项B：告诉镇长 → 镇长介入，走官方路线
  - 选项C：谁都不告诉 → 保留信息优势，但张铁匠可能受害
- 这些选项由AI叙事引擎（`rolling_story_generator.py`）在生成事件时自动纳入玩家已知信息

**时机选择**（通过NPC状态影响事件结果）：
- NPC当前的情绪状态（`SET_EMOTION`）影响同一选项的效果差异
- AI叙事引擎在生成对话时读取NPC当前状态，自然调整反应强度

**信息拼图**（通过NPC记忆系统实现）：
- 不同NPC掌握事实的不同碎片（`npc_memory.py`）
- 玩家从多个NPC对话中收集信息碎片，事件系统在检测到关键信息组合时解锁新选项
- 与感知过滤系统配合：NPC知道的信息质量取决于感知途径

11.3 二阶效应——可学习的玩家技能

二阶效应指的是"你的行动通过社会网络产生的间接影响"。这是从新手到高手的关键成长维度。

**上手层**（一阶思维）：
- "我帮了张铁匠 → 张铁匠对我好感提升" → 直接因果，容易理解

**精通层**（二阶思维）：
- "我帮了张铁匠 → 张铁匠的好友李大婶也对我好感提升 → 但张铁匠的对手赵掌柜觉得我在选边站 → 赵掌柜可能会在背后说我坏话 → 影响还不认识我的NPC对我的初始印象"
- 高手会在行动前预判这种连锁反应，并利用它：
  - 在赵掌柜面前帮张铁匠 → 逼赵掌柜表态（激化矛盾，可能有利于你）
  - 私下帮张铁匠 → 赵掌柜不知道，不激化矛盾（但也不能公开利用）

**与涟漪系统的关系**：
- 涟漪系统是二阶效应的后端实现（第5.7节）
- 信息战略系统是二阶效应的前端呈现——玩家需要能逐渐学会预判涟漪传播的方向和强度
- 随着游戏进行，玩家对镇上的关系网络越来越熟悉，预判二阶效应的能力自然提升——这就是"精通"的过程

11.4 玩家信息面板

复用和扩展已有UI面板来支撑信息战略：

- **命运图谱**（已有 `fate_graph_ui.py`）：可视化NPC关系网络，随玩家获取信息逐步揭露连线
- **NPC详情面板**（已有 `npc_detail_panel.py`）：展示已知的NPC信息、态度、关系
- **新闻面板**（已有 `live_news_panel.py`）：记录已发生的事件，充当"已知信息"的时间线
- **侧边栏要务区**（已有 `sidebar.py`）：提示当前最紧急的信息缺口和行动建议


十二、玩家开局与势力博弈

12.1 设计问题与核心解法

12.1.1 现有设计的结构性缺陷

当前设计存在一个根本问题：**玩家在游戏中没有足够的个人利害关系**。

所有动态事件都是NPC的人生节点——张铁匠的困境、赵掌柜被骚扰——玩家的角色本质上是"路过的好心人"。这导致三个问题互相加强：

| 问题 | 表现 | 根因 |
|------|------|------|
| 数值养成缺乏自利动机 | "我为什么要练力量到45？"——因为某个NPC可能需要帮忙。不够。 | 数值提升只服务于他人的事件选项，不服务于自己的生存 |
| 仇敌主线太"远" | 威胁度是一个缓慢增长的数字，前20天几乎感受不到个人危险 | 威胁度只触发叙事节点，不改变游戏规则 |
| 三条线互相脱节 | 生存压力、NPC事件、仇敌威胁各自独立运转 | 没有一个统一的矛盾把它们串起来 |

```
当前的三条线（脱节的）：

  生存压力（饿了冷了）  ←── 独立运转，和NPC事件无关
  NPC人生节点           ←── 独立运转，和玩家命运无关
  仇敌威胁度            ←── 独立运转，只是一个慢涨的数字

  三者之间没有"因为A所以必须做B"的因果链
```

对比冰汽时代：你挖煤不是因为"NPC需要煤"，而是因为**你自己的人会冻死**。煤炭=0→全城冻死，这个因果链让每一铲煤都有重量。本游戏需要等价的因果链。

12.1.2 核心解法：城镇争夺战

将游戏的核心矛盾重新定义为**城镇争夺战**——玩家和敌对势力争夺对城镇NPC和建筑的影响力：

```
┌──────────────────────────────────────────┐
│              城 镇 = 战 场               │
│                                          │
│    玩家势力 ◄─── 中立区 ───► 敌方势力    │
│    (蓝色)        (灰色)      (红色)      │
│                                          │
│  每个NPC = 一个争夺点                    │
│  每个建筑 = 一个战略节点                 │
│  每次帮助NPC = 争取一个点                │
│  每次敌方施压 = 对方夺取一个点           │
│                                          │
│  胜利 = 蓝色覆盖足够多的关键节点         │
│  失败 = 红色吞噬了整个城镇              │
└──────────────────────────────────────────┘
```

这个框架让所有现有系统产生了统一的意义：

- **数值养成**：我的力量/智力/魅力决定我能争夺哪些NPC和建筑
- **NPC事件**：每个NPC人生节点都是一次争夺战——我帮NPC不是善举，是阻止敌方扩张
- **社交关系**：盟友网络 = 我的控制区，越大我越安全
- **生存压力**：关键建筑被敌方控制 → 我的生存循环被直接打断（铁匠铺没了→武器没法修→打不过人→更多东西被抢）
- **仇敌威胁度**：不只是一个数字，而是驱动敌方AI实际行动的参数——每涨一段，游戏规则就变一次

```
修复后的三条线（统一的）：

  生存压力 ←──┐
              ├── 全部指向同一个核心矛盾：城镇控制权
  NPC事件  ←──┤
              │   帮NPC = 保住我的资源渠道 = 自保
  敌方威胁 ←──┘   敌方侵蚀 = 我的日常循环被削弱 = 切身之痛
```

12.2 玩家初始状态

12.2.1 开局设定

玩家以"逃难者"身份抵达城镇，一无所有：

| 属性 | 初始值 | 体感 |
|------|--------|------|
| HP | 70（受伤） | 逃难途中受了伤，需要休养 |
| 饱食度 | 20（饥饿） | 再不吃东西明天就掉血 |
| 寒冷值 | 40（偏冷） | 衣衫褴褛，入夜会更冷 |
| 铜钱 | 5 | 几乎买不起任何东西 |
| 住所 | 无 | 露宿=每晚寒冷值+15 |
| 所有NPC好感 | 0 | 没有任何人认识你 |
| 能力属性 | 全部10 | 最低水平 |

**设计意图**：

1. **多重压力但不致命**：饱食度20意味着明天开始掉血，但今天不会死。给玩家1-2天的缓冲窗口来解决最紧急的问题。
2. **强制进入社交循环**：你不可能靠一个人解决所有问题——5铜买不起一顿饭+一晚住宿（合计需要20-25铜），必须和人打交道（打工、做委托、求助）。
3. **第一个帮你的人会被记住**：当所有NPC都是0好感的陌生人时，第一个给你机会的人会成为强烈的情感锚点。这个人日后被敌方威胁时，玩家的保护欲是发自内心的，不是义务驱动的。

12.2.2 开局主线

玩家抵达城镇后，主线任务自动触发：

```
主线任务："在城中站稳脚跟"
├── 阶段1：活下来（找到食物和住处）
├── 阶段2：有收入（稳定的经济来源）
├── 阶段3：有根基（至少1个好感≥50的NPC）
└── 阶段4：有势力（加入或创建势力）
```

这条主线贯穿前10天左右，每个阶段完成时给予成就感反馈，同时自然过渡到仇敌威胁主线。阶段3完成时，仇敌的渗透行动开始产生可感知的影响——玩家刚站稳脚跟，脚下的地就开始被抽走。

12.3 住所与据点系统

12.3.1 住所进阶

玩家的住所是**社会地位的物理映射**——每一级升级都依赖社交关系，不是纯粹花钱。住所在中期自然过渡为据点（见12.3.2），两者合一。

| 阶段 | 住所形态 | 获取条件 | 保暖效果 | 存储 | 风险 |
|------|----------|----------|----------|------|------|
| 0 | 露宿（城隍庙） | 初始 | 寒冷+15/晚 | 无 | 随时被赶走 |
| 1 | 客栈租房 | 任一NPC好感≥10 + 每日10铜 | 寒冷+5/晚 | 小 | 断钱即被赶出 |
| 2 | NPC收留 | 某NPC好感≥50（主动邀请） | 寒冷+0/晚 | 中 | 该NPC出事则失去住所 |
| 3 | **破院子→据点** | 铜钱≥300 + 某NPC好感≥40（帮忙牵线）| 寒冷-5/晚 | 大 | 可被敌方袭击 |
| 4 | 势力总部 | 据点阶段3 + 盟友≥5人 | 寒冷-10/晚 | 共享仓库 | 需组织防守 |

**关键设计原则**：

1. **住所升级是社交关系的副产品**：你不是在"建房子"，而是在"赢得信任"。张铁匠说"你搬我这儿来住吧"的那一刻，比买一栋房子更有成就感。

2. **每一级住所都可被敌方威胁**：
   - 客栈被敌方收购 → 房租翻倍或被赶走
   - 收留你的NPC被威胁 → 你可能被迫搬走，或者你得保护这个NPC
   - 据点被袭击 → NPC受伤、设施损坏，需要修复
   - 势力总部被围攻 → 需要组织盟友集体防守

3. **住所阶段2是叙事高光**：当一个NPC好感到50，主动说"你要不嫌弃，搬到我这儿来吧"——这是玩家在这个城镇被第一次真正接纳。从这一刻起，你和这个NPC的命运绑定了。

4. **住所阶段3是据点的起点**：玩家不是"建"了一个据点，而是通过社交关系获得了城内一处废弃院落的使用权，然后通过招募盟友让它逐步成长为有功能的据点。

12.3.2 据点系统——NPC就是设施

**核心理念**：据点的成长方式不是"建造建筑"，而是"招人进来"。每招一个NPC盟友加入据点，据点就多一个功能。NPC就是设施。

```
┌──────────────────────────────────────────────────┐
│                 据点成长逻辑                      │
│                                                  │
│  传统SOC：     采集资源 → 建造设施 → 解锁功能    │
│  本游戏：     培养NPC → 招募入驻 → 解锁功能     │
│                                                  │
│  帕鲁的基地：帕鲁在里面干活                      │
│  本游戏据点：NPC盟友在里面提供服务               │
│                                                  │
│  区别：NPC有自己的意志、需求和故事               │
│       他们不是被你"放置"的，是被你"说服"来的    │
└──────────────────────────────────────────────────┘
```

**据点位置**：城内废弃院落。初期无人注意的角落，随着NPC入驻逐步变成有人气的场所。位于城中意味着：
- 与城内NPC的日常互动无额外路程成本
- 据点本身是城镇争夺地图的一部分——你的据点就在敌方势力范围旁边
- 据点的存在感随成长越来越明显，也越来越容易成为敌方目标

**NPC入驻机制**：

| 条件 | 说明 |
|------|------|
| 好感≥70 | NPC对你忠诚，才愿意搬来和你共事 |
| 据点有空位 | 每阶段有NPC容量上限 |
| NPC主动提出或玩家邀请 | 好感到70时，NPC可能主动说"我搬来帮你吧"；或玩家主动邀请 |
| NPC无冲突 | 两个互相敌对的NPC不会同时入驻（需要玩家先调解） |

**每个NPC带来的据点功能**（通过卡牌堆叠配方实现）：

| NPC职业 | 入驻后解锁的据点功能 | 对应卡牌堆叠配方 |
|---------|---------------------|-----------------|
| 铁匠 | 打造/修复武器 | 铁矿+铁匠NPC=铁剑；武器+铁匠NPC=修复武器 |
| 大夫 | 治伤/制药 | 草药+大夫NPC=伤药；玩家+大夫NPC=治疗 |
| 商人 | 交易/寄卖 | 物品+商人NPC=出售获利；铜钱+商人NPC=采购物资 |
| 武师 | 训练力量/敏捷 | 玩家+武师NPC=训练（效率高于城中公共设施） |
| 读书人 | 训练智力/获取情报 | 玩家+读书人NPC=学习；线索+读书人NPC=分析情报 |
| 手艺人 | 制作日用品/修缮据点 | 木材+手艺人NPC=家具；石材+手艺人NPC=加固围墙 |

**NPC品质影响产出**：同样是"铁矿+铁匠=铁剑"，但铁匠的好感度和在据点的时间越长，产出品质越高。这让NPC培养有了持续价值——不是招来就完了，维护关系依然重要。

**据点成长阶段**：

```
阶段1：破院子（Day 10左右获得）
┌─────────────────────────┐
│                         │
│    [空地]    [破屋]     │
│                         │
│    容量：1-2个NPC       │
│    功能：基本存储       │
│    防御：无             │
└─────────────────────────┘

  获取方式：某NPC好感≥40，告诉你城东有个没人要的破院子，
  花300铜买下/租下使用权。
  第一个NPC入驻是重大里程碑——"终于有人愿意跟我干了"。

阶段2：小营地（3-4个NPC入驻后自动升级）
┌─────────────────────────┐
│                         │
│  [铁匠台] [医馆]       │
│  [训练场] [集市]       │
│                         │
│    容量：3-4个NPC       │
│    功能：多个NPC服务    │
│    防御：简单围墙       │
└─────────────────────────┘

  视觉变化：院子里出现了NPC的工作设施，有人进出。
  从外面路过能看到里面有人在忙活。
  敌方开始注意到这个据点的存在。

阶段3：势力据点（5-8个NPC + 正式建立势力后）
┌─────────────────────────┐
│                         │
│  [铁匠铺] [医馆]       │
│  [练武场] [商铺]       │
│  [议事厅] [仓库]       │
│                         │
│    容量：5-8个NPC       │
│    功能：完整服务       │
│    防御：防御工事       │
└─────────────────────────┘

  视觉变化：院子已经变成一个小型社区。
  进出的NPC形成了人流，成为城中一个显眼的存在。
  敌方将其视为必须拔除的目标。

阶段4：势力总部（10+个NPC + 势力成型后）
┌─────────────────────────┐
│                         │
│  完整的小型社区          │
│  所有核心功能齐备        │
│  NPC有分工和日程         │
│                         │
│    容量：10+个NPC       │
│    功能：可下达指令      │
│    防御：完整防御体系    │
└─────────────────────────┘

  这就是你"从无到有建立的势力"的物理形态。
  每一个NPC都是你一个一个说服来的。
  每一个设施都是某个人的技能在发挥作用。
```

**据点被攻击时的玩法影响**：

据点不是无敌的。当敌方威胁度足够高（≥50）时，敌方可能袭击据点：

| 袭击类型 | 后果 | 恢复方式 |
|---------|------|---------|
| 骚扰 | 据点功能效率降低50%持续2天 | 自动恢复 |
| 破坏 | 某个设施损坏，对应NPC功能暂时不可用 | 投入资源修复（铜钱+材料） |
| 围攻 | 全据点功能停摆，NPC可能受伤 | 组织盟友防守/反击 |
| 渗透 | 敌方收买据点中的某个NPC | 揭露间谍/说服NPC回心转意 |

**设计意图**：据点被攻击时，你的反应不是"数字降了"，而是"张铁匠受伤了，铁匠台坏了，我的武器修不了了"——具体的、和人绑定的损失。保护据点就是保护你的朋友，不是保护一堆数字。

12.3.3 据点与城镇公共设施的关系

据点内的NPC服务和城镇公共建筑提供类似功能，但有关键区别：

| 维度 | 城镇公共设施 | 据点内NPC服务 |
|------|-------------|--------------|
| 所有权 | 属于NPC/势力，可被敌方控制 | 属于你，只有你能用 |
| 效率 | 标准效率 | 高效率（NPC好感越高效率越高） |
| 稳定性 | 可能被敌方占领后不可用 | 只要NPC在且据点没被破坏就可用 |
| 成本 | 需要付费 | 免费或低成本（盟友帮忙） |
| 获取难度 | 走过去就能用 | 需要先招募NPC到据点 |

**设计意义**：城镇公共设施是"公共资源"，你和敌方在争夺使用权；据点是"私有资源"，是你的退路和根基。即使城里的铁匠铺被敌方控制了，只要你据点里有铁匠，你依然能修武器。但据点也不是无敌的——敌方可以直接攻击你的据点。

这就形成了两个战场的博弈：
- **城中**：争夺公共资源的控制权（影响所有人）
- **据点**：守住私有资源的安全（只影响你和盟友）

12.3.4 据点的质变里程碑

据点成长中有几个关键的"质变时刻"，提供远超数值增长的成就感：

| 里程碑 | 触发条件 | 体验 |
|--------|---------|------|
| 第一个NPC入驻 | 首个NPC好感≥70并同意加入 | "终于有人愿意跟我干了"——从独行侠变成有同伴 |
| 据点自给自足 | 3个不同职业NPC入驻 | 据点内可以满足基本的修理/治疗/训练需求，不再完全依赖城镇 |
| 第一次成功防守 | 敌方袭击据点，玩家组织NPC防守成功 | "这是我的地盘，我守住了"——据点从"住的地方"变成"必须保护的东西" |
| 据点成为势力总部 | 正式建立势力 | 从破院子到势力总部的视觉对比是最直观的成长证明 |
| NPC之间产生互动 | 据点内多个NPC形成自己的社交关系 | 据点不再是"你+一堆NPC"，而是一个活的小社区 |

12.4 敌对势力框架

12.4.1 组织结构

敌对势力是一个有层级的组织，通过渐进式渗透来控制城镇：

```
┌─────────────────────────────────────────────────────┐
│                  敌对势力组织结构                      │
│                                                     │
│  ┌───────────┐                                      │
│  │ 幕后主使   │  不在城中，远程指挥                   │
│  │           │  玩家的终极仇敌                       │
│  └─────┬─────┘                                      │
│        │                                            │
│  ┌─────▼─────┐                                      │
│  │ 城中代理人  │  1-2人，公开或半公开身份              │
│  │           │  负责整体策略：经济渗透、拉拢收买      │
│  │           │  表面可能是正当商人/官员               │
│  └─────┬─────┘                                      │
│        │                                            │
│  ┌─────▼─────┐                                      │
│  │ 中层执行者  │  3-5人，各负责一个方面               │
│  │           │  商铺管理、情报收集、武力威慑          │
│  │           │  是玩家在中期的主要对手               │
│  └─────┬─────┘                                      │
│        │                                            │
│  ┌─────▼─────┐                                      │
│  │ 底层打手   │  10-20人，流动性强                    │
│  │           │  执行具体任务：巡逻、骚扰、收保护费   │
│  │           │  是玩家在早期的直接威胁               │
│  └───────────┘                                      │
└─────────────────────────────────────────────────────┘
```

**设计原则**：
- 组织结构定义角色类型和行为逻辑，具体人名/背景故事由内容策划填充
- 每一层有不同的对抗方式：底层可以武力驱赶，中层需要智谋或社交，代理人需要揭露其身份或切断其支持
- 幕后主使是终局对手，前期只通过代理人的行为间接感知其存在

12.4.2 敌方行为逻辑

敌方不是"到了某个威胁度就做某件事"的脚本，而是有自己的**目标-手段-资源**逻辑的AI系统：

**目标**：控制城镇（经济、政治、武力三个维度的控制度）

**手段选择**：基于当前局势和玩家状态动态调整

| 敌方评估维度 | 低阻力时的手段 | 高阻力时的手段 |
|-------------|--------------|--------------|
| 经济 | 低价倾销、正常收购 | 断供、封锁贸易路线 |
| 社交 | 拉拢中立NPC、施小恩惠 | 威胁、株连、制造谣言 |
| 武力 | 巡逻示威、小规模骚扰 | 定向打击、围困 |

**关键机制——敌方也有资源约束**：
- 敌方的行动消耗资源（金钱、人手、幕后主使的耐心）
- 玩家的对抗可以消耗敌方资源（打退打手→敌方损失人手，揭露商铺→敌方损失经济据点）
- 敌方不是无限强大的——它也在和时间赛跑（幕后主使不会无限期投入资源）
- 这让玩家的每一次成功对抗都有实质意义，不是"打退一波又来一波"的无意义循环

**与AI导演的关系**：
- AI导演（第5.4节）负责叙事节奏和情绪控制
- 敌方AI负责敌对势力的具体行动决策
- 两者协同：AI导演可以延迟或加速敌方行动的触发时机，但不改变行动内容
- 导演的"连续施压≤3天"保护规则对敌方行动同样生效

12.5 敌对势力的玩法级威胁

**核心原则：敌人的每一步行动，都应该让玩家的日常玩法循环变得更难、更贵、或直接不可用。**

叙事威胁 vs 玩法威胁——两者的区别是本章的设计核心：

| | 叙事威胁（避免） | 玩法威胁（追求） |
|--|---|---|
| 表现 | 弹通知、威胁度数字增长、NPC对话提及 | 玩家依赖的功能被削弱或移除 |
| 感受 | "哦，知道了" | "靠，我的收入来源没了" |
| 应对动机 | 应该做点什么（义务感） | 必须做点什么（生存需要） |
| 示例 | "威胁度34→36" | "集市打工收入从50降到30了" |

12.5.1 四维侵蚀模型

敌对势力通过四个维度同步侵蚀玩家的生存基础，每个维度都对应玩家日常循环中的具体环节：

```
┌──────────────────────────────────────────────────────┐
│              敌对势力四维侵蚀模型                      │
│                                                      │
│  ┌──────────┐                 ┌──────────┐           │
│  │ 经济侵蚀  │                 │ 空间侵蚀  │           │
│  │ 赚钱变难  │                 │ 地盘缩小  │           │
│  │ 花钱变多  │                 │ 功能缺失  │           │
│  └────┬─────┘                 └────┬─────┘           │
│       │                            │                 │
│       ▼                            ▼                 │
│   ┌──────────────────────────────────────┐           │
│   │       玩家日常循环被压缩              │           │
│   │  (可用时间、资源、选项持续减少)       │           │
│   └──────────────────────────────────────┘           │
│       ▲                            ▲                 │
│       │                            │                 │
│  ┌────┴─────┐                 ┌────┴─────┐           │
│  │ 社交侵蚀  │                 │ 军事威胁  │           │
│  │ 盟友流失  │                 │ 人身安全  │           │
│  │ 关系衰减  │                 │ 资源被抢  │           │
│  └──────────┘                 └──────────┘           │
└──────────────────────────────────────────────────────┘
```

**① 经济侵蚀——赚钱变难，花钱变多**

敌方通过经济手段挤压玩家的资源循环，让"活下去"本身的成本持续上升：

| 阶段 | 敌方行动 | 对玩家日常循环的影响 | 触发条件 |
|------|---------|---------------------|---------|
| 渗透 | 在城中开低价商铺，吸引客源 | 本地商人收入下降→委托报酬降低→玩家打工收入-20% | 威胁度≥15 |
| 挤压 | 收购或胁迫本地商铺 | 部分商铺物价上涨30-50%；原有公开委托减少 | 威胁度≥30 |
| 垄断 | 控制主要贸易路线 | 粮食/药材价格翻倍；某些物资断供 | 威胁度≥50 |
| 封锁 | 切断城镇对外通道 | 城外采集/送货类任务不可用；物价全面暴涨 | 威胁度≥70 |

玩家对抗手段：
- 保护本地商人（阻止收购）→ 维持正常物价和委托来源
- 建立替代供给（找走私渠道、与外部势力合作）→ 绕过封锁
- 经济反击（揭露敌方低价倾销目的→NPC联合抵制）
- 釜底抽薪（破坏敌方商铺、切断敌方资金链）

**② 空间侵蚀——玩家可用的功能场所缩减**

敌方控制建筑后，改变建筑的可交互内容。玩家将卡牌拖向被控制建筑时，原有的配方不再生效：

| 建筑被控制 | 丧失的玩法功能 | 替代方案 | 替代方案的代价 |
|-----------|---------------|---------|--------------|
| 铁匠铺 | 无法训练力量、无法修复武器 | 城外野练/找游方铁匠 | 效率降低50%，耗时增加 |
| 酒馆 | 无法打探情报、无法接取部分委托 | 只能通过NPC闲聊获取 | 信息碎片化，线索不完整 |
| 集市 | 打工收入大幅下降 | 城外采集/私下交易 | 耗时更多，收入更低 |
| 药铺 | 无法买药、受伤恢复变慢 | 采集草药自制 | 效果差、需要智力门槛 |
| 城门 | 无法正常出城 | 翻墙/密道 | 需要敏捷≥30，有被发现风险 |
| 书院 | 无法训练智力 | 找有学问的NPC请教 | 需要好感≥30，效率低 |

视觉表现：被控制的建筑卡牌边框变红，上方出现敌方势力标记。玩家尝试与被控制建筑交互时，弹出提示说明该区域已被控制，并给出替代方案的模糊指引。

**③ 社交侵蚀——最核心的威胁**

社交网络是玩家的核心资产（第2.1节），因此社交侵蚀是敌方最致命的武器：

| 手段 | 机制 | 玩法影响 |
|------|------|---------|
| 威胁NPC | 好感<40的NPC：每天对玩家好感自动-3（恐惧衰减） | 中立NPC加速疏远，社交圈萎缩 |
| 收买NPC | 向利己型（主义=利己）/缺钱NPC开价 | NPC倒向敌方，可能泄露玩家情报 |
| 株连NPC | "谁帮这个外来人，就是跟我们作对" | 玩家的盟友也开始被施压→产生新的NPC人生困境 |
| 制造谣言 | 通过谣言系统（`rumor_system.py`）散布对玩家不利的信息 | 未接触过的NPC初始好感降低 |

**关键机制——社交衰减**：

当威胁度≥30时，好感<40的NPC每天对玩家好感自动-3（恐惧衰减）。这意味着：
- 你不仅需要"建设"关系，还需要"维护"关系——和侵蚀赛跑
- 3天不理一个中立NPC，他可能从中立变成冷淡
- 你的时间在"拓展新盟友"和"维护旧关系"之间被撕扯
- **好感≥40的NPC不受恐惧衰减影响**——这就是"铁杆盟友"的价值，也是为什么要把关系推到40以上

**株连机制的深层设计**：

当玩家的盟友（好感≥50的NPC）被敌方施压时，会触发该NPC的新人生困境——"因为帮你而被威胁"。这让NPC事件和玩家个人命运彻底绑定：

```
张铁匠帮过你 → 敌方威胁张铁匠
→ 张铁匠人生困境触发："是继续帮这个外来人，还是为了家人屈服？"
→ 这不再是"别人的故事"，而是"因为我连累了他"
→ 如果你不帮张铁匠 → 失去住处+失去盟友+失去铁匠铺功能
→ 如果你帮张铁匠 → 消耗资源+暴露自己+可能触发更多株连
```

**④ 军事威胁——人身安全**

| 威胁类型 | 触发条件 | 玩法影响 |
|---------|---------|---------|
| 巡逻骚扰 | 威胁度≥20，夜间外出 | 概率遭遇敌方巡逻→战斗或躲避，消耗HP/时间 |
| 勒索保护费 | 威胁度≥30，每3-5天一次 | 铜钱-30~-50，不交则遭报复（物资损失、住处被砸） |
| 定向打击 | 玩家公开对抗敌方后 | 伏击（HP大量损失）、财物被抢、住所被破坏 |
| 围困封锁 | 威胁度≥70 | 连续3天行动范围受限，必须用储备资源撑过去 |

玩家对抗手段：
- 提升战斗力直接应对（力量/敏捷/装备）
- 发展情报网提前预警（盟友NPC通风报信）
- 组织盟友集体防御（势力到一定规模后）
- 向官方势力求助（如果与官府关系够好）

12.5.2 威胁度与敌方行动对照表

将现有威胁度系统（第5.2节）扩展为驱动敌方具体行动的参数。**每一个阶段不是"弹一个通知"，而是"改变一条游戏规则"**：

| 威胁度 | 阶段 | 敌方行动 | 对玩家日常循环的实质影响 |
|--------|------|---------|----------------------|
| 0-15 | 潜伏 | 暗中侦察，不直接行动 | 无直接影响。偶尔有陌生人出现（伏笔信息） |
| 15-30 | 渗透 | 经济渗透+夜间巡逻 | 打工收入-20%；夜间外出有遭遇风险 |
| 30-50 | 挤压 | 收购商铺+威胁NPC+收保护费 | 物价上涨30-50%；社交衰减启动（好感<40每日-3）；定期经济损失 |
| 50-70 | 控制 | 占领关键建筑+收买/孤立NPC | 部分训练/情报功能不可用；盟友被株连；替代方案效率减半 |
| 70-85 | 压制 | 封锁+军事围困+全面施压 | 出城受限；物资紧缺；盟友被迫站队表态 |
| 85-100 | 决战 | 全面摊牌 | 所有积累进入结算——盟友数量、资源储备、势力规模决定终局选项 |

12.5.3 压力螺旋与正向螺旋

敌方的四维侵蚀会形成**负向压力螺旋**——一个维度的恶化加剧其他维度：

```
负向螺旋（敌方主导）：
经济被挤压 → 没钱维护关系（送礼/帮忙需要资源）
  → 关系开始衰减 → 盟友减少
    → 没人帮你守卫/通风报信
      → 军事威胁增大 → 受伤/被抢
        → 更缺钱 → 螺旋加速
```

反过来，玩家的有效对抗可以形成**正向螺旋**：

```
正向螺旋（玩家主导）：
保护一个商人 → 物价不涨 → 经济稳定
  → 有余力帮更多NPC → 盟友增多
    → 盟友互相保护 → 敌方行动成本上升
      → 敌方被迫收缩 → 玩家控制区扩大
        → 更多资源渠道 → 螺旋加速
```

**设计要点**：玩家的每一次选择都在这两个螺旋之间拉扯。帮张铁匠→短期消耗资源（负向压力），但保住了铁匠铺功能和一个盟友（正向螺旋的基础）。这就是"每个选择都让玩家纠结"（体验目标G1）在系统层面的落地。

12.6 玩家势力感的体现

玩家的"势力"不是一个独立数值面板，而是弥漫在日常玩法每一个细节中的综合体感。

12.6.1 城镇控制地图

城镇地图上的建筑和NPC通过视觉标记反映势力归属：

| 标记颜色 | 含义 | 判定条件 |
|---------|------|---------|
| 灰色 | 中立 | 初始状态 / NPC好感在0~49之间 |
| 蓝色 | 玩家盟友 | NPC好感≥50，或建筑主人为玩家盟友 |
| 红色 | 敌方控制 | 被敌方收买/威胁/占领 |
| 金色 | 玩家据点 | 玩家的据点（12.3.2节） |

玩家打开地图时，一眼就能看出当前的势力格局：

```
游戏初期（Day 1-5）：

│  [铁匠]灰  [集市]灰  [药铺]灰         │
│  [民居]灰  [民居]灰  [城门]灰         │
│                                       │
│  → 全灰，你是一个nobody               │

中期（Day 15-25，敌方渗透 + 玩家发展）：

│  [官府]灰  [商铺]红  [酒馆]蓝         │

┌───────────────────────────────────────┐
│  [官府]蓝  [商铺]蓝  [酒馆]蓝         │

12.6.2 日常体感变化

势力感不是看面板数字，而是体现在玩家的日常游戏体验中：

| 势力阶段 | 街上的体感 | 事件中的体感 | 经济体感 |
|---------|-----------|------------|---------|
| 无势力（Day 1-3） | NPC不理你，走路没人打招呼 | 只有保底选项可选 | 打工勉强糊口 |
| 初有根基（Day 4-10） | 熟人NPC主动打招呼 | 2-3个选项可选 | 有余钱但不宽裕 |
| 小有势力（Day 10-20） | 走在盟友区域，NPC主动示好；敌方小喽啰不敢在此区域搞事 | 多数选项可选，偶尔解锁"找人帮忙"类高级选项 | 有稳定收入来源 |
| 形成势力（Day 20+） | 中立NPC也开始主动示好；敌方在你的控制区行动需要权衡代价 | "动员盟友""集体施压"等高级选项解锁 | 可调动势力资源 |

12.6.3 势力感的核心体现：敌方动你的代价在变

势力感最直观的体现，是敌方"动你"的成本随你的社交网络增长而上升：

```
Day 3（无势力）：
  敌方打手在街上推搡你
  → 没人帮你，只能自己扛或跑

Day 10（有3个盟友）：
  敌方打手想找你麻烦
  → 张铁匠从铺子里走出来："有什么事跟我说。"
  → 对方掂量一下，骂骂咧咧走了

Day 20（有势力）：
  敌方想对你动手
  → 需要先瓦解你的盟友网络，才敢对你下手
  → 这就是为什么"社交侵蚀"是敌方在中期的核心战术

Day 30（势力成型）：
  敌方要动你 = 动你的整个网络
  → 代价太高，被迫选择全面决战或和谈
  → 游戏进入终局阶段
```

12.7 开局体验流（Day 1-7）——任务系统如何串联体验

以下用完整的7天流程展示任务系统如何驱动玩家的开局体验。每个关键节点标注了**驱动它的任务类型、触发人和触发时机**，对应 `dynamic-task-system/design.md` 中的任务体系。

**任务类型速查**（详见任务系统设计文档 §5.2）：

| 标记 | 任务类型 | 来源 | 触发条件 | 槽位 |
|------|---------|------|---------|------|
| 【主线】 | 主线任务 | 系统/剧情 | 剧情节点自动推进 | 1个，始终存在 |
| 【生存】 | 生存任务 | 玩家状态 | HP<30/饱食度<30/寒冷>60/铜钱<30 | 1个，状态恢复后消失 |
| 【委托】 | 公开委托 | NPC发布 | 告示板辰时刷新，随时可接 | 不限 |
| 【情报】 | 情报委托 | 当事NPC | 起幕事件余韵后，当事NPC委托 | 1个 |
| 【势力】 | 势力任务 | 势力上司 | 卯时，玩家无活跃势力任务时 | 1个（Day 1-7未涉及） |

**Day 1-7 任务出场时序**：

```
Day 1         Day 2         Day 3         Day 4         Day 5         Day 6         Day 7
  │             │             │             │             │             │             │
【生存】      【委托】      【委托】      【委托】       起幕事件     【情报】      【情报】
饱食度<30     告示板接取     持续做委托    持续做委托     ↓            收集线索      线索汇总
  │             │             │             │          【情报】         │           准备应对
【主线】        │           闲聊获取       住所升级     当事NPC委托      │             │
亥时触发        │           敌方信息       机会          │             敌方渗透      三线交汇
              小冲突                                    │             玩法影响      承幕临近
              (事件)                                    │
                                                      【生存】
                                                      铜钱<30?
```

```
═══════════════════════════════════════════════════
                   Day 1 · 抵达
═══════════════════════════════════════════════════

【巳时 09:00】玩家抵达城镇

  状态：HP 70，饱食度 20（饥饿警告），铜钱 5，无住所

  → 【生存任务·自动触发】饱食度 20 < 阈值 30
    任务面板显示："肚子快饿扁了，得赶紧找点吃的"
    触发人：无（系统根据状态阈值自动生成）
    消失条件：饱食度恢复到 ≥30

  城镇对你来说完全陌生：
  - 所有NPC好感=0，没人主动搭理你
  - 走到商铺前，老板面无表情看你一眼
  - 告示板上贴着几张本地事务的告示，你谁都不认识


【午时 11:00】第一个选择——怎么解决吃饭问题

  生存任务驱动玩家行动，但不指定具体方式。
  玩家通过探索城镇自然发现多种解法：

  去集市打零工（玩家卡+集市卡=打工）
    → 耗时2时辰，铜钱+15
    → 但你不认识任何商家，只能做最苦最累的活

  去城外采集（玩家卡+城外=采集）
    → 耗时1时辰，获得野果x2（每个饱食度+10）
    → 免费，但产出低，而且你不熟悉地形

  去酒馆碰运气
    → 老板娘看你灰头土脸：
      "小伙子，看你这样子是赶路来的吧。
       帮我把后院那两箱酒搬进来，管你一顿饭。"
    → 耗时1时辰，饱食度+30，老板娘好感+10
    → 饱食度≥30，【生存任务·自动消失】
    → 【设计意图】这是游戏引导玩家进入社交循环的第一个钩子
       ——帮人做事=吃饱饭+建立关系，比纯打工划算
       生存任务把玩家推出去，社交奖励把玩家拉进来


【申时 15:00】第二个压力——住处

  饱食度暂时解决了，但天色渐晚，需要找住处。

  → 【生存任务·自动触发】铜钱 5 < 阈值 30
    任务面板显示："身上没几个钱了，得想办法赚点"
    （此任务与住处压力叠加，但系统只显示一个生存任务）

  去客栈问价：
    "一晚10铜。先付后住。"
    → 如果打了工有15铜：可以住，但明天又得从0开始赚
    → 如果只有5铜：住不起

  如果之前帮了酒馆老板娘（好感10）：
    老板娘："今晚先在后院将就一宿吧，别睡大街上。"
    → 免费住一晚，寒冷值不增加
    → 【设计意图】玩家第一次切身体会到：关系=资源
       有人帮你一把，比10铜更值钱

  如果没帮老板娘：
    只能去城隍庙露宿
    → 寒冷值+15，第二天体力更差


【亥时 21:00】休息

  睡前内心独白（引出主线动机）：
  "总算活过了今天...可我不能一直这样。
   那些人迟早会找到这里，我得在这座城站稳脚跟。"

  → 【主线任务·剧情触发】"在城中站稳脚跟"
    触发人：系统（玩家内心独白）
    任务面板正式出现主线追踪
    阶段目标：找到稳定住所、建立收入来源、在城中站住脚

  → 【设计意图】主线任务不是Day 1白天出现的
    ——白天玩家忙着活命，没有余力想长远。
    只有晚上躺下来，才自然地开始想"接下来怎么办"。
    这让主线任务的出现是情感驱动的，不是系统强塞的。

Day 1 任务总结：
  ├── 【生存】饱食度<30 → 驱动玩家进城觅食 → 遇到酒馆老板娘

**任务系统如何驱动体验的设计要点**：

1. **任务类型的出场顺序是精心设计的**：生存任务（Day 1）→ 公开委托（Day 2）→ 主线推进（Day 4）→ 情报委托（Day 5）。每种任务在玩家最需要它的时候出现，教学负荷分散到一周内。

2. **不是所有体验都由任务驱动**：Day 1的酒馆老板娘互动、Day 2的小冲突、Day 3的闲聊获得敌方信息——这些是事件系统和社交系统的产出，不需要包装成任务。任务系统负责"给玩家明确的事做"，而非"包揽所有体验"。

3. **势力任务在Day 1-7不出现**：玩家尚未加入任何势力，没有上司给你派活。势力任务要到玩家有了一定社交基础、被势力注意到之后才会开放，这是后续阶段的内容。

4. **情报委托是"准备感"的核心载体**：Day 5起幕事件后自动产生，给玩家2天时间收集线索、针对性准备。这2天不是空白等待期，而是有目标的探索——去找谁打听、该练什么、该攒多少钱。

5. **任务系统反映世界状态**：敌方渗透不只是叙事描述，它直接影响公开委托的报酬数值（NPC生意变差→出得起的钱变少）。玩家在任务面板上就能感受到世界在变化。

12.8 设计约束与边界

1. **据点不是自由建造系统**：据点的成长方式是"招人"不是"建房"。玩家不能自由放置建筑、设计布局。据点的功能完全由入驻NPC决定，视觉变化是自动的。这确保核心体验始终是"经营人"而非"经营物"。

2. **城镇控制地图不是RTS**：玩家不直接"攻占"建筑或指挥NPC。控制权的变化通过社交手段间接实现——你通过影响建筑主人的立场来改变建筑归属，不是率兵攻打。

3. **敌方AI不是全知的**：敌方的行动受感知过滤器约束（第5.8.2节）。玩家的暗中行动不会被立即发现——如果你偷偷调查敌方商铺，只有目击者知道。这让潜行/调查类手段有实际战术价值。

4. **压力有上限**：与AI导演的"连续施压≤3天"保护规则配合（第5.4.2节），敌方不会在同一周内同时发动四维侵蚀的最高强度。螺旋加速有上限，避免玩家陷入无解的死局。

5. **玩家始终有保底生存路线**：即使所有城镇建筑被敌方控制，据点内的NPC服务仍然可用（除非据点也被攻破）。即使据点被攻破，仍有城外采集、私下交易等最低限度生存方式。游戏允许"很难"但不允许"无解"。

6. **敌方行动可被逆转**：被控制的建筑可以通过帮助原主人夺回；被收买的NPC可以通过揭露敌方真面目争取回来；被破坏的据点可以修复。没有"一次失误万劫不复"的设计。

7. **NPC利益绑定是自然的，不是强制的**：游戏不会强制提示"张铁匠被赶走你就没地方修武器了"。这个因果关系由玩家自己发现和感受——当你真的需要修武器却发现铁匠铺被占了的时候，那个"靠"的感觉比任何提示都强烈。

8. **据点NPC依然是独立个体**：入驻据点的NPC不会变成"你的员工"。他们有自己的需求金字塔（第6节）、会有自己的人生困境、可能因为不满而离开、也可能被敌方策反。据点里的人需要持续维护关系，不是"招来就万事大吉"。
