## Context

设计Doc里的时间流逝系统基于12时辰：
- 时间自然流逝，玩家自由行动不受回合限制
- 不同时段有不同的事件触发倾向
- 玩家可以随时选择做什么，时间持续推进

但当前存在两个问题解决的问题：
1. **预告信息是被动阅读**：玩家看完就走，没有转化为行动目标
2. **事件间隙无焦点**：玩家不知道该做什么

**核心洞察**：将预告信息转化为NPC委托，让"获取信息"变成玩法的一部分。

**现有系统支撑**：
- QuestManager：单主线任务追踪，支持多种任务类型
- NPC闲聊系统：已有基础对话功能
- AI导演系统：已有预告信息生成（公告栏、NPC态度变化）

## Goals / Non-Goals

**Goals:**
1. 将预告信息转化为NPC委托玩家搜集情报的任务
2. 让闲聊成为获取任务线索的玩法，推动社交系统使用
3. 建立生存自发布任务，强化"数值无感"的压力感
4. 建立势力任务系统：玩家可加入或自创势力，上司发布任务
5. 保持轻量化，不做复杂的任务链系统

**Non-Goals:**
1. 不做复杂的任务链和任务依赖
2. 不做无发布人的"系统任务"
3. 不做每日签到式任务

**关键洞察**：
- **不是单向帮助**：任务系统不是"帮助"应对事件，而是**响应事件系统的要求**
- **动态调整**：事件根据玩家准备情况提供不同选项，准备越好选择越多
- **连锁反应**：事件结果会触发新的事件，提出新的养成要求
- **长期规划**：玩家需要根据预告的事件序列，规划自己的养成路线

#### 1.4 任务的本质

所有任务都由以下要素构成：
- **发布人**：谁发布的任务
- **接取人**：谁来完成任务
- **发布渠道**：私下委托 vs 公开告示
- **报酬**：金钱/人情/物品/信息/关系

#### 1.5 任务分类维度

**按来源分类**：

| 任务类型 | 来源 | 触发时机 | 核心目的 | 典型报酬 |
|---------|------|---------|---------|---------|
| **情报委托** | 相关NPC | 起承转合幕前 | **提示准备方向** | 信息+关系+金钱 |
| **势力任务** | 势力上司 | 每日卯时刷新 | **提升地位资源** | 贡献+金钱+道具 |
| **公开委托** | NPC/玩家 | 随时发布 | **解决具体需求** | 约定的报酬 |
| **生存任务** | 玩家自己（系统触发） | 状态阈值/事件选项 | **维持生存** | 生存本身 |

**生存任务的两种触发方式**：

| 触发方式 | 说明 | 示例 |
|---------|------|------|
| **状态阈值触发** | 玩家状态触犯阈值 | 饱食度<30 → "得找点吃的" |
| **事件选项触发** | 玩家选择导致必须完成某事才能生存 | 选择武力对抗 → "击退高府打手" |

**事件选项触发的生存任务**：

当玩家选择某个选项后，可能触发一个"必须完成"的任务：

```
【示例：武力对抗】

玩家选择："谁敢动张大哥的铺子，先过我这关！"
→ 对话结束后，高府打手不肯罢休
→ 触发生存任务："击退高府打手"

任务要素：
├── 发布人：玩家自己（因为选择了对抗）
├── 接取人：玩家（强制）
├── 发布渠道：无（即时触发）
├── 报酬：生存 + 声望/关系变化
└── 失败后果：受伤甚至死亡
```

**为什么算"玩家自己发布的任务"**：
- 玩家主动选择了武力对抗
- 选择就意味着承担后果
- 击败对方是"自己选择的道路"，不是别人强制
- 不击败对方自己就会受伤害

**按发布渠道分类**：

| 渠道 | 可见性 | 报酬要求 | 特点 |
|------|--------|----------|------|
| **私下委托** | 仅双方可见 | 可以不写（人情交换） | 熟人之间，灵活 |
| **江湖告示板** | 所有人可见 | 必须写明报酬 | 陌生人，需明确条件 |

### 2. NPC人生困境事件与情报委托

**重要区分**：
- **NPC人生困境事件**：AI导演驱动的叙事事件，围绕NPC的desire vs misgiving展开
- **情报委托**：相关NPC发布的私人任务，帮助玩家为即将到来的事件做准备
- **势力任务**：玩家所在势力的上司发布的任务，用于提升势力地位（见第3节）

#### 2.1 NPC人生困境事件（起承转合）

**核心洞察**：AI导演会随机触发NPC的人生困境事件，每个困境遵循"起承转合"四幕结构。每一幕的选项都必须明确考验玩家的**能力属性**、**背包资源**或**社交关系**。

**四幕的选项设计原则**：

每个选项都包含以下字段：

| 字段 | 含义 | 何时结算 |
|-----|------|---------|
| `requirement` | 门槛条件 | 选择前检查，不满足则无法选择 |
| `cost` | 即时消耗 | 剧情对话结束后结算（如触发后续任务则为null） |
| `effect` | 即时收益 | 剧情对话结束后结算（如触发后续任务则为null） |
| `transfer` | 资源转移 | 剧情对话结束后结算（如触发后续任务则为null） |
| `triggers_task` | 触发后续任务 | 选择后剧情对话结束时生成任务 |

**两种结算方式**：

1. **即时结算**：`cost`/`effect`/`transfer` 有值，`triggers_task` 为 null
   - 剧情对话结束后直接结算
   - 例：劝张妥协 → 关系-15，高府关系+10

2. **触发后续任务**：`cost`/`effect`/`transfer` 为 null，`triggers_task` 有值
   - 剧情对话结束后生成新任务
   - 任务完成后再结算最终结果
   - 例：武力对抗 → 触发生存任务"击退高府打手"

**triggers_task 字段结构**：

```yaml
triggers_task:
  task_type: "任务类型"（战斗/收集/调查/传递等）
  source_type: "来源类型"（生存任务/情报委托/势力任务等）
  title: "任务标题"
  publisher: "发布人"（PLAYER 或 NPC_ID）
  description: "任务描述"
```

**任务类型（按内容分类）**：

| task_type | 说明 | 示例 |
|-----------|------|------|
| 战斗任务 | 击败敌人/保护某人 | 击退高府打手、护送NPC |
| 收集任务 | 收集资源/物品/金钱 | 筹集80铜、收集木材x10 |
| 调查任务 | 收集情报/打探消息 | 打听高府真实目的 |
| 传递任务 | 送信/传话 | 把这封信送给张三 |

**来源类型（按来源分类）**：

| source_type | 说明 | 发布人 |
|-------------|------|-------|
| 生存任务 | 玩家自己触发的必须完成任务 | PLAYER |
| 情报委托 | NPC发布的委托 | NPC_ID |
| 势力任务 | 势力上司发布的任务 | 上司NPC_ID |
| 公开委托 | 公开告示板上的任务 | 发布任务的NPC_ID |

**发布人判定逻辑**：

| 情况 | source_type | 发布人 | 说明 |
|-----|-------------|-------|------|
| 玩家主动选择的对抗/挑战 | 生存任务 | `PLAYER` | 选择=承担后果，不完成自己会受损 |
| 事件当事人请求帮助 | 情报委托 | 当事NPC_ID | NPC请求玩家帮忙做某事 |

**选项选择后的剧情流程**：

```
【1. 开场对话 intro】（8-10句）
├── 场景开幕（旁白）
├── 冲突展示（对立方发言）
├── 当事人回应
├── 群众反应
├── 冲突升级
├── 氛围收紧
└── 交给玩家 → 弹出选择界面

【2. 玩家做出选择】

【3. 选项后续对话 choice_dialogues】（5-7句）
├── 玩家登场（说出选择对应的台词）
├── 群众惊讶（对玩家介入的反应）
├── 各方反应（对立方、当事人的回应）
├── 交锋推进（对话或动作）
├── 群众议论
└── 余韵收尾（旁白）

【4. 结算或触发后续】
├── 即时结算：结算 cost/effect/transfer
└── 触发任务：生成后续任务（如战斗、收集、调查）
    └── 任务完成后再结算最终结果
```

**关键洞察**：
- 选项选择后**不会立刻中断剧情**
- 而是先有一段**现场对话**展示各方反应
- 对话结束后才进行结算或触发后续任务
- `cost`/`effect`/`transfer` 不是"点击选项瞬间生效"，而是"剧情对话结束后结算"

**示例：武力对抗选项的完整流程**：

```
【intro - 冲突展示】
高府打手："张铁匠，三天之内不搬，就别怪兄弟们不客气！"
张铁匠："各位爷，行行好，我这铺子是祖传的..."
群众："这帮人太欺负人了..."
旁白："围观的你，会怎么做？"
→ 弹出选择界面

【玩家选择：武力对抗】

【choice_dialogues - 现场反应】
```

**设计目标**：让玩家了解局势，建立情感连接，选择立场

- 门槛较低：大部分玩家可以选大部分选项
- 成本较低：让玩家可以轻松尝试不同立场

- 不同选项考验不同**能力属性**：力量/魅力/智力
- 保底选项：无门槛但有负面后果

### 四幕设计的核心洞察

**不是"每幕只考验一种维度"，而是**：

| 幕 | 设计侧重点 | 实际考验维度 | 例子 |
|---|-----------|-------------|------|
| **起** | 低成本试探 | 主要考验关系，但也可以有属性门槛 | 选项C需要wit≥20才能质疑 |
| **承** | 必须有门槛 | 主要考验属性，但也可以消耗资源 | 选项B需要charm≥40+消耗金钱 |
| **转** | 高消耗抉择 | 主要考验资源，但也可以有属性/关系门槛 | 选项C需要wit≥40+关系≥50+道具 |
| **合** | 面对后果 | 综合考验，根据之前选择动态生成 | 不同转幕选择生成不同合幕选项 |

**关键设计原则**：
1. **每个选项都是多维度的**：可以同时有requirement（门槛）、cost（消耗）、effect（收益）
2. **门槛设计创造养成动力**：玩家看到"力量≥45"的选项，就会想去提升力量
3. **消耗设计创造资源压力**：玩家需要权衡"现在付出"vs"未来收益"
4. **不同选项考验不同维度**：让玩家有选择养成方向的自由

**AI导演如何生成线索任务**：

```python
# 伪代码：AI导演生成线索任务
def generate_clue_quest(dilemma_seed, target_phase):
    """
    根据困境种子和目标阶段，生成线索任务
    """
    # 1. 分析即将发生的事件
    upcoming_event = predict_next_event(dilemma_seed, target_phase)
    
    # 2. 提取可能的能力需求
    stat_requirements = extract_stat_requirements(upcoming_event)
    # 例如：{"strength": 50, "agility": 30, "money": 100}
    
    # 3. 生成线索任务
    clue_quest = {
        "title": f"打听{upcoming_event['npc_name']}的近况",
        "description": f"听说{upcoming_event['hint']}...",
        "required_clues": 3,  # 需要收集3条线索
        "hint_stats": stat_requirements,  # 暗示的能力需求
        "reward": {
            "insight": f"真相：{upcoming_event['truth']}",
            "preparation_time": "3天"  # 距离事件发生的时间
        }
    }
    
    return clue_quest
```

### 2.4 情报委托的设计

**来源：AI导演的预告信息**

AI导演在宏观决策时生成预告信息，比如：
- "镇上出现了陌生人"
- "有人在打听玩家"
- "某个NPC被威胁了"

### 5. 12时辰与任务触发

**决定：任务触发与时辰相关，但不限制玩家行动**

#### 5.1 时辰系统概述

游戏时间以12时辰为单位自然流逝：

| 时辰 | 时间 | 时段特点 | 任务触发倾向 |

#### 5.2 任务触发与时辰

**情报委托**：
- 触发时段：辰时（07:00-09:00）
- 触发方式：NPC主动找到玩家
- 不强制：如果玩家在睡觉或忙碌，NPC会等待或留言

**势力任务**：
- 触发时段：卯时（05:00-07:00）
- 触发方式：上司NPC找到玩家
- 特点：每日刷新，玩家可以选择接取或拒绝

**生存任务**：
- 触发条件：玩家状态触犯阈值
- 触发方式：玩家内心独白
- 特点：随时可能触发，与时辰无关

**公开委托**：
- 更新时段：辰时（07:00-09:00）
- 更新内容：NPC发布的新委托、过期的委托清除
- 玩家可以随时查看和接取
- 告示板24小时可见，但新委托在辰时刷新

#### 5.3 玩家自由行动

**核心原则**：
- 玩家可以随时做任何事，不受"回合"限制
- 行动会消耗时间，时间推进到不同时辰
- 不同时辰有不同的事件触发概率

**行动示例**：
```
当前：辰时 08:00
玩家选择：去铁匠铺闲聊
→ 耗时30分钟 → 辰时 08:30
→ 可能触发：情报委托线索、随机事件

玩家选择：去集市工作赚钱
→ 耗时2时辰 → 午时 12:00
→ 获得铜钱+50
→ 可能触发：午时事件
```

#### 5.4 事件触发机制

**事件触发概率与时辰**：
```
子时-丑时：夜间事件概率 ×1.5（暗杀、盗窃、秘密交易）
卯时-辰时：日常事件概率 ×1.2（任务发布、社交活动）
午时：事件高发期 ×2.0（冲突、商业、公共事件）
申时-酉时：黄昏事件概率 ×1.3（冲突爆发、势力活动）
其他时辰：基准概率 ×1.0
```

**玩家控制时间流逝**：
- 正常速度：时间自然流逝
- 加速：玩家选择"休息"或"等待"时，时间快速推进
- 暂停：玩家打开菜单、对话时，时间暂停

### 5. 线索系统与起承转合的技术实现

#### 5.1 线索任务生成时机

AI导演在生成起承转合各幕事件前，**必须**先生成对应的线索任务：

```python
class StoryDirector:
    def generate_next_beat(self, dilemma_seed):
        """生成下一个故事节拍"""
        current_phase = dilemma_seed.current_phase
        next_phase = self._get_next_phase(current_phase)
        
        # 1. 先生成线索任务（在事件触发前）
        clue_quest = self._generate_clue_quest(dilemma_seed, next_phase)
        if clue_quest:
            self._publish_clue_quest(clue_quest)
        
        # 2. 计算事件触发时间（给玩家准备时间）
        trigger_time = self._calculate_trigger_time(clue_quest)
        
        # 3. 安排事件触发
        self._schedule_event(dilemma_seed, next_phase, trigger_time)
    
    def _generate_clue_quest(self, dilemma_seed, target_phase):
        """根据目标阶段生成线索任务"""
        # 分析即将发生的事件
        upcoming_event = self._predict_event(dilemma_seed, target_phase)
        
        # 提取能力需求（用于线索提示）
        stat_requirements = self._extract_stat_requirements(upcoming_event)
        
        # 根据阶段生成不同类型的线索
        clue_types = {
            StoryPhase.EMERGE: "预告线索",
            StoryPhase.ESCALATE: "准备线索", 
            StoryPhase.CLIMAX: "真相线索",
            StoryPhase.SETTLE: "回响线索"
        }
        
        return ClueQuest(
            type=clue_types[target_phase],
            target_event=upcoming_event,
            stat_hints=stat_requirements,
            required_clues=3,  # 需要收集的线索碎片数
            preparation_time="2-3天"  # 距离事件触发的时间
        )
```

#### 5.3 线索收集机制

```python
class ClueSystem:
    def collect_clue(self, player, npc, quest_id):
        """玩家与NPC闲聊时收集线索"""
        quest = self.get_active_quest(quest_id)
        
        # 检查NPC是否拥有该任务的线索
        if not self.npc_has_clue(npc, quest):
            return None  # NPC没有线索，正常闲聊
        
        # 获取线索碎片
        clue_fragment = self.get_clue_fragment(npc, quest)
        
        # 记录玩家收集的线索
        quest.add_collected_clue(clue_fragment)
        
        # 检查是否收集足够
        if quest.is_complete():
            # 生成完整情报
            insight = self.generate_insight(quest)
            return {
                "type": "clue_complete",
                "insight": insight,
                "stat_hints": quest.stat_hints,
                "time_until_event": quest.preparation_time
            }
        
        return {
            "type": "clue_fragment",
            "fragment": clue_fragment,
            "progress": f"{quest.collected_count}/{quest.required_clues}"
        }
```

### 9. 势力任务系统

**背景：游戏世界中存在各式各样的势力，玩家可以选择加入或自创势力。**

#### 9.1 势力的存在形式

**势力数据结构**：
```python
class Organization:
    org_id: str           # 势力ID，如 "kaifeng_fu", "tianshui_alley"
    org_name: str         # 势力名称，如 "开封府", "甜水巷商会"
    power_type: str       # 势力类型：士/农/工/商/学/兵/游/匪/民
    leader_id: int        # 势力领袖 NPC ID
    members: List[int]    # 成员 NPC ID 列表
    
    # 势力层级关系
    hierarchy: Dict[int, int]  # {下属ID: 上司ID} 映射
```

**势力层级结构**：
```
势力领袖 (LEADER, rank 5)
    └── 头目 (MANAGER, rank 4)
        └── 干部 (SENIOR, rank 3)
            └── 成员 (MEMBER, rank 2)
                └── 新人 (ROOKIE, rank 1)
```

#### 9.2 玩家加入势力

**加入方式**：
1. **主动申请**：玩家向势力领袖或干部申请加入
   - 需要满足条件：好感度 >= 30，或完成入门任务
   - 领袖点头后正式加入，获得 rank 1（新人）

2. **被邀请加入**：NPC主动邀请玩家加入
   - 条件：玩家对该势力有大贡献，或与领袖关系极好
   - 跳过入门考核，直接获得 rank 2

**加入势力后的变化**：
- 获得上司：根据层级分配直接上司
- 解锁势力任务：可以从上司处接取任务
- 势力声望：在该势力内的功勋值，影响晋升

#### 9.3 玩家自创势力

**条件**：
1. 玩家声望 >= 100（有一定社会地位）
2. 资金 >= 1000铜（启动资金）
3. 有至少 2 名 NPC 愿意追随（好感度 >= 70）

**自创流程**：
```
1. 玩家选择"创建势力"
2. 选择势力类型（士/农/工/商/学/兵/游/匪）
3. 命名势力
4. 选择初始据点（需要拥有或购买建筑）
5. 邀请追随者加入
6. 正式成立，玩家成为领袖
```

**自创势力的特点**：
- 玩家是领袖，没有上司
- 可以下达任务给成员NPC
- 可以扩张势力范围（占领建筑）
- 可以与其他势力建立关系（结盟/敌对）

#### 9.4 上司发布任务

**任务发布机制**：

```
┌─────────────────────────────────────────────────┐
│ 时辰触发：势力任务刷新（卯时 05:00-07:00）         │
├─────────────────────────────────────────────────┤
│ 卯时时段：                                        │
│ ├── 上司检查势力任务池                            │
│ ├── 根据玩家职级筛选可用任务                       │
│ └── 上司主动找到玩家分配任务                       │
└─────────────────────────────────────────────────┘
```

**机制说明**：
- 势力任务每日卯时刷新
- 如果玩家当时在睡觉，上司会留言或等待玩家醒来
- 玩家有整个白天的时间决定是否接取
- 未接取的任务次日卯时重置

**上司找玩家的对话形式**（太阁风格）：
```
上司NPC走到玩家面前：
"小李，有件事需要你去办..."

对话选项：
[接下任务]
[询问详情]
[婉言拒绝]（可能影响评价）
```

**势力任务类型**：

| 任务类型 | 描述 | 示例 |
|---------|------|------|
| 收集物资 | 为势力筹集资源 | "去收这个月的保护费，收齐500铜" |
| 巡逻任务 | 守卫势力领地 | "去东边那条街转转，看看有什么异样" |
| 战斗任务 | 与敌对势力交战 | "黑风寨的人来了，去教训他们一顿" |
| 情报任务 | 刺探其他势力信息 | "去打听一下商会最近在搞什么鬼" |
| 护送任务 | 保护重要人物或物资 | "把这批货送到城外去，别出差错" |

**任务奖励与晋升**：
```
完成任务 → 获得【功勋】(faction_fame)
功勋累积 → 触发晋升考核 → 职级提升

职级提升的好处：
- 解锁更多任务类型
- 可以下达任务给下级成员
- 获得势力资源分成
- 最终可成为领袖
```

#### 9.5 势力任务与情报委托的区别

| 维度 | 情报委托 | 势力任务 |
|------|---------|---------|
| 发布人 | 友好的NPC | 玩家的上司 |
| 触发条件 | AI导演预告 | 加入势力后每日刷新 |
| 拒绝后果 | 好感略降 | 影响晋升，严重可能被踢出 |
| 奖励 | 好感、少量金钱 | 功勋、职级、势力资源 |
| 失败后果 | 无惩罚 | 降低功勋，可能影响地位 |

#### 9.6 势力任务槽位设计

```
玩家任务面板：
┌─────────────────────────────────────┐
│ 🏠 势力任务 (最多 2 个)              │
├─────────────────────────────────────┤
│ [开封府] 查案 - 收集证词 (2/5)       │
│ [开封府] 巡逻 - 夜间守备 (进行中)    │
└─────────────────────────────────────┘

- 势力任务最多同时接 2 个
- 高职级玩家可以同时接更多
- 领袖自创势力没有势力任务（而是分配任务给下属）
```

### 10. 玩家发布委托任务

**背景：玩家也可以发布任务，让NPC来帮忙完成。**

#### 10.1 发布渠道选择

| 渠道 | 可见性 | 报酬要求 | 适用场景 |
|------|--------|----------|----------|
| **江湖告示板** | 所有人可见 | 必须写明报酬 | 找人帮忙完成具体任务 |
| **私下委托** | 仅目标NPC可见 | 可以不写 | 请熟人帮忙，人情交换 |

#### 10.2 江湖告示板发布流程

```
1. 玩家走到告示板位置
2. 选择"发布委托"
3. 填写委托内容：
   - 标题（必填）：如"【悬赏】寻找失踪的货物"
   - 详细描述：任务要求和背景
   - 报酬类型：金钱/物品/人情
   - 报酬数量：具体数值
   - 截止时间：几天内有效
   - 是否匿名：隐藏发布人身份（额外收费）
4. 支付发布费用：报酬的5%作为手续费
5. 委托出现在告示板，等待NPC接取
```

### 11. NPC发布与接取委托

**背景：NPC也可以发布委托到告示板，同时NPC也会接取玩家发布的委托。**

#### 11.1 NPC发布委托的触发条件

**NPC需求检测**：
```
NPC每日检测自身状态：
├── 生存需求未满足 → 发布"采集/购买物资"委托
├── 安全受威胁 → 发布"护卫/调查"委托
├── 商业需求 → 发布"送货/采购"委托
├── 复仇需求 → 发布"悬赏仇人"委托
├── 社交需求 → 发布"寻人/送信"委托
└── 势力需求 → 发布"势力相关"委托
```

**NPC委托生成示例**：
```
触发：张铁匠急需铁矿石
生成委托：
- 标题：【求助】收购铁矿石
- 描述：炉子断料了，急需铁矿石30块，愿意溢价收购
- 报酬：60铜（市场价40铜）
- 截止：2天
```

#### 11.2 NPC委托的报酬计算

```python
def calculate_npc_reward(npc, task_type):
    """NPC根据自身经济状况决定报酬"""
    base = TASK_BASE_REWARD[task_type]  # 基础报酬
    
    if npc.wealth == "RICH":
        return int(base * 1.5)  # 富人给得多
    elif npc.wealth == "POOR":
        return int(base * 0.7)  # 穷人给得少
    else:
        return base
```

#### 11.3 NPC接取玩家委托的AI逻辑

**决策因素**：
```python
def npc_decide_accept_commission(npc, commission):
    """NPC决定是否接取委托"""
    score = 0
    
    # 1. 能力匹配
    if npc_can_do(npc, commission):
        score += 30
    else:
        return False  # 做不了直接拒绝
    
    # 2. 报酬吸引力
    if commission.reward_type == "GOLD":
        score += commission.reward_amount / 10
    elif commission.reward_type == "FAVOR":
        # 根据与发布人的关系计算价值
        relation = get_relation(npc, commission.publisher_id)
        score += relation * 2
    
    # 3. 时间充裕度
    if npc.is_busy():
        score -= 20
    
    # 4. 性格倾向
    if npc.has_trait("GREEDY"):
        score += 15  # 贪财的更容易接
    if npc.has_trait("LAZY"):
        score -= 20  # 懒惰的不爱接
    if npc.has_trait("BRAVE"):
        score += 10  # 勇敢的不怕危险任务
    
    # 5. 与发布人的关系（非匿名）
    if not commission.is_anonymous:
        relation = get_relation(npc, commission.publisher_id)
        if relation >= 50:
            score += 20  # 帮朋友
        elif relation < 0:
            score -= 30  # 不帮讨厌的人
    
    return score >= 50  # 达到阈值才接取
```

#### 11.4 NPC接取后的执行

**执行流程**：
```
NPC接取委托后：
1. 将委托加入NPC的任务队列
2. 根据优先级安排执行时间
3. 执行过程中可能：
   ├── 成功完成 → 找发布人领取报酬
   ├── 失败放弃 → 委托重新挂回告示板
   └── 超时未完成 → 委托过期
```

**NPC执行委托的可见性**：
- 玩家可以在告示板看到"已被接取"状态
- 玩家可能看到NPC在执行任务（如在集市看到NPC在收购铁矿石）
- 完成后NPC会主动找玩家结算

#### 11.5 委托完成与结算

**结算流程**：
```
接取人完成任务目标 → 系统检测完成状态 → 自动结算：
├── 扣除发布人报酬
├── 增加接取人报酬
├── 增加双方好感度（+5）
└── 记录委托完成历史

如果发布人报酬不足：
├── 委托失败
├── 发布人信誉下降
└── 接取人好感度下降（-10）
```

**超时处理**：
```
委托超时未完成：
├── 自动取消
├── 退还发布人报酬（扣除手续费）
└── 接取人信誉下降
```

#### 11.6 江湖告示板的位置

**物理位置**：
- **主城广场**：最繁忙，委托最多，预告信息最全
- **各势力据点**：势力相关委托和预告
- **村镇入口**：本地小委托和区域预告

**访问方式**：
- 直接走到告示板位置
- 与告示板旁的NPC对话查看

## Risks / Trade-offs

| 风险 | 缓解措施 |
|------|----------|
| 任务干扰事件节奏 | 情报委托只推送1个，不堆积 |
| 玩家不知道要去找谁 | 任务描述给出模糊提示（"问问镇上的人"） |
| 线索重复无聊 | 预设多种线索文本，AI生成变体 |
| 生存任务变成噪音 | 只在状态真正危险时触发，状态恢复后自动消失 |
| 势力任务太像打工 | 任务有叙事包装，且可以选择性拒绝 |
| 自创势力门槛太高 | 分步解锁，允许小额起步后逐步扩张 |
| 委托任务没人接 | NPC有主动接取AI，且报酬合理时优先接 |
| 告示板委托太多 | 自动清理过期委托，最多显示20条 |
| 玩家发布委托被NPC坑 | 委托完成后才支付报酬，有信誉系统 |

## Open Questions

1. **情报委托失败怎么办？**
   - 倾向：不设失败，只是"未完成"，事件照样触发

2. **多个情报委托冲突怎么办？**
   - 倾向：同时最多1个情报委托，新委托要等旧的完成或放弃

3. **放弃委托的惩罚？**
   - 倾向：无惩罚，但发布人好感可能略微下降（-5），且不再发布

4. **玩家加入势力后又想退出怎么办？**
   - 倾向：可以退出，但会损失该势力功勋的50%，且该势力好感度下降

5. **玩家自创势力后想加入其他势力？**
   - 倾向：需要先解散自己的势力，或与其他势力合并（特殊机制）

6. **上司不在场怎么发布任务？**
   - 倾向：上司会在卯时主动找玩家；如果玩家在睡觉，会留言等待；如果上司死亡/离开，系统自动分配新上司

10. **玩家睡觉时会错过重要事件吗？**
    - 倾向：关键事件会等待玩家醒来；非关键事件会记录日志供玩家查看；紧急事件（如被袭击）会强制唤醒玩家

11. **时间流逝速度如何控制？**
    - 倾向：正常速度（1秒=1游戏分钟）；加速（休息/等待时 1秒=10游戏分钟）；暂停（菜单/对话时）

7. **玩家发布委托后想取消怎么办？**
   - 倾向：可以取消，但手续费不退；如果已被接取，需要支付违约金（报酬的20%）

8. **NPC接取委托后一直不完成怎么办？**
   - 倾向：超时后自动取消，委托重新挂回告示板；NPC信誉下降

9. **委托任务和情报委托/势力任务冲突吗？**
   - 倾向：不冲突，玩家可以同时接取多种任务，但每种有各自的槽位限制
