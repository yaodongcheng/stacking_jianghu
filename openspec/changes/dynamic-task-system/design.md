## 1. 设计目标与问题定义

### 1.0 设计框架：社会系统的三层目标结构

本游戏的核心挑战是面对"一群人"组成的动态社会系统（详见 designDoc §2.1）。任务系统的设计服务于这个三层目标结构：

| 层级 | 目标 | 任务系统的作用 |
|------|------|--------------|
| **Macro（终极目标）** | 让社会系统到达目标状态——壮大关系网对抗仇敌 | 第二层玩法循环：长期目标牵引 |
| **Meso（阶段目标）** | 改变关键NPC的立场——每个NPC人生节点是一次阶段转换 | 第二层玩法循环：事件应对 + 情报委托 |
| **Micro（即时操作）** | 观察→策略→行动→反馈的循环 | 第一层玩法循环：日常经营（任务执行、资源准备） |

关键设计原则：
- 玩家在任何时刻都必须知道自己在"朝着什么前进"——任务系统提供这个焦点
- Micro层的"准备感"是核心体验（§4.3），区别于传统RPG的线性任务流
- 上手层：接任务→做任务→获得成长；精通层：预判二阶效应、理解信息价值、把握时机

### 1.1 当前系统

游戏时间，有很多天，每天有12时辰：
- 时间自然流逝，玩家自由行动不受回合限制
- 不同时段有不同的事件触发倾向
- 玩家可以随时选择做什么，时间持续推进

玩家初始状态（详见 designDoc §12.2）：

| 属性 | 初始值 | 体感 |
|------|--------|------|
| HP | 70（受伤） | 逃难途中受了伤，需要休养 |
| 饱食度 | 20（饥饿） | 再不吃东西明天就掉血 |
| 寒冷值 | 40（偏冷） | 衣衫褴褛，入夜会更冷 |
| 铜钱 | 5 | 几乎买不起任何东西 |
| 住所 | 无 | 露宿=每晚寒冷值+15 |
| 所有NPC好感 | 0 | 没有任何人认识你 |
| 能力属性 | 全部10 | 最低水平 |

设计意图：多重压力但不致命（饱食度20意味着明天掉血，但今天不会死），强制进入社交循环（5铜买不起一顿饭+一晚住宿），第一个帮你的人会成为强烈的情感锚点。

已有系统支撑：
- QuestManager：单主线任务追踪，支持多种任务类型
- NPC闲聊系统：已有基础对话功能，接入LLM
- AI导演系统：已有Npc命运节点，对应起承转合四幕的新闻

### 1.2 要解决的问题

1. **事件间隙无焦点**：玩家不知道每个A事件和B事件的空白过程应该准备什么，缺乏目标动机
2. **数值变化缺乏具象抓手**（配合 designDoc 问题1）：数值系统已定义，但玩家缺少"我差多少/我够不够"的日常感知。任务系统通过门槛（力量≥45才能选武力对抗）、消耗（筹集80铜）、报酬（完成委托+50铜）将抽象数值转化为具体的"够/不够"体验，是数值有感的玩法载体
3. **开局缺乏个人利害关系**：NPC人生困境对刚进游戏的玩家来说是"别人的故事"。需要先建立玩家自己的利害关系（住所、收入、社交），NPC困境才能与玩家利益自然绑定，而不是让玩家以旁观者身份去关心陌生人的问题

### 1.3 核心洞察

A事件结束后，对B事件的预告信息转化为NPC委托，让"获取信息"变成玩法的一部分。

### 1.4 设计目标

1. 将预告信息转化为NPC委托玩家搜集情报的任务
2. 让闲聊成为获取任务线索的玩法，推动社交系统使用
3. 建立生存自发布任务，强化"数值无感"的压力感
4. 建立势力任务系统：玩家可加入或自创势力，上司发布任务
5. 保持轻量化，不做复杂的任务链系统

## 2. 核心玩法循环（长期循环）

**终极目标**：壮大社交圈，对抗主线来袭的敌人

玩法循环分为三层，每一层服务于下一层：

```
┌───────────────────────────────────────────────────────────────────┐
│                                                                   │
│  【第一层：日常经营】                                              │
│   接任务 → 做任务 → 获得成长（能力↑ / 金钱↑ / 关系↑ / 道具↑）     │
│                          │                                        │
│                          ▼                                        │
│  【第二层：事件应对】                                              │
│   遇事件 → 做选择 → 影响世界（NPC命运 / 关系变化 / 口碑传播）     │
│                          │                                        │
│                          ▼                                        │
│  【第三层：长期目标】                                              │
│   壮大关系网 → 积累实力 → 对抗主线（抵御外敌 / 保护小镇 / 决定结局）│
│                                                                   │
│  ─────────────────────────────────────────────────────────────── │
│  三层之间的驱动关系：                                              │
│  • 做任务是为了【提升自己】                                        │
│  • 提升自己是为了【在事件中有更好的选项】                           │
│  • 事件中的选择是为了【壮大社交圈】                                │
│  • 壮大社交圈是为了【对抗主线敌人】                                │
└───────────────────────────────────────────────────────────────────┘
```

### 2.1 长期节奏

| 时间段 | 玩家活动 | 阶段目标 | 主要任务驱动 |
|-------|---------|---------|------------|
| Day 1 | 抵达：解决饱食和住处 | 活下来 | 【生存】饱食度<30自动触发 → 驱动探索城镇 |
| Day 2 | 扎根：告示板接委托、初见冲突事件 | 建立经济循环 | 【委托】辰时告示板刷新 → 赚钱+建立NPC关系 |
| Day 3-4 | 融入：持续做委托、闲聊获敌方信息、住所升级 | 初步社交网络 | 【委托】持续 + 【主线】阶段推进（住所升级） |
| Day 5 | 第一个NPC人生困境起幕 + 情报委托触发 | 感受"准备感" | 【情报】当事NPC委托打听 → 收集3条线索 |
| Day 6-7 | 情报收集 + 敌方渗透可感知 + 针对性准备 | 为承幕做准备 | 【情报】执行 + 【委托】报酬受敌方影响下降 |
| Day 8-11 | 第一个困境承转合三幕 | 获得第一个铁杆盟友 | 情报→准备→事件应对 |
| Day 12-18 | 第二个NPC人生困境 | 再获盟友，社交圈开始成型 | 同上，可能叠加势力任务 |
| Day 19-30 | 积累3-5个铁杆盟友，加入/自创势力 | 信息渠道增多，资源稳定 | 势力任务成为常规内容 |
| Day 30+ | 主线敌人来袭 | 调用关系网联合对抗，盟友多→选项多→胜算大 | 全任务类型协同 |

> **设计意图**：Day 1-4 是"玩家的故事"——先让玩家通过主线任务和生存压力理解这个世界的规则、建立对城镇的归属感。NPC人生困境从 Day 5 开始登场，此时它是"配菜"而非"主菜"——玩家已经有了自己的利害关系（住所、收入、社交），NPC的困境才能与玩家的利益自然绑定，而不是让玩家以旁观者身份去关心陌生人的问题。

### 2.2 任务系统与事件系统的双向循环

任务系统和事件系统不是"任务帮助应对事件"的单向关系，而是双向驱动：

```
  ┌──────────┐     提出要求（预告未来事件门槛）    ┌──────────┐
  │  事件系统  │ ──────────────────────────────► │  任务系统  │
  │ (AI导演)  │                                 │ (玩家驱动) │
  │          │ ◄────────────────────────────── │          │
  └──────────┘     检验准备成果（玩家能力/资源）   └──────────┘
        ▲                                            │
        │          玩家行动                           │
        └─────── 接任务 → 做任务 → 提升自己 ──────────┘
```

1. **事件系统提出要求**：AI导演安排未来事件，预判所需能力/资源
2. **通过任务系统传达要求**：发布情报委托，暗示玩家准备方向（如"高府派了三个打手"→暗示可能需要武力或金钱）
3. **玩家通过任务提升自己**：针对性地接取任务，提升属性、攒钱、维护关系
4. **事件检验准备成果**：事件触发时，根据玩家准备情况提供不同选项（力量够→可武力对抗；金钱够→可出钱调解；都没准备→只能妥协）
5. **事件结果驱动新一轮循环**：选择的后果触发后续事件，提出新的养成目标

### 2.3 任务类型出场时序

任务类型的出场顺序经过精心编排，每种任务在玩家最需要它的时候出现，教学负荷分散到一周内。

**任务类型速查**（详见 §5.2）：

| 标记 | 任务类型 | 来源 | 触发条件 | 槽位 |
|------|---------|------|---------|------|
| 【生存】 | 生存任务 | 玩家状态 | HP<30%/饱食度<30/寒冷>60/铜钱<30 | 1个，状态恢复后消失 |
| 【委托】 | 公开委托 | NPC发布 | 告示板辰时刷新，随时可接 | 不限 |
| 【主线】 | 主线任务 | 系统/剧情 | 剧情节点自动推进 | 1个，始终存在 |
| 【情报】 | 情报委托 | 当事NPC | 起幕事件余韵后，当事NPC委托 | 1个 |
| 【势力】 | 势力任务 | 势力上司 | 卯时，玩家无活跃势力任务时 | 1个（Day 1-7未涉及） |

**Day 1-7 出场时序图**：

```
Day 1         Day 2         Day 3         Day 4         Day 5         Day 6         Day 7
  │             │             │             │             │             │             │
【生存】      【委托】      【委托】      【委托】       起幕事件     【情报】      【情报】
饱食度<30     告示板接取     持续做委托    持续做委托     ↓            收集线索      线索汇总
  │             │             │             │          【情报】         │           准备应对
【主线】        │           闲聊获取       住所升级     当事NPC委托      │             │
亥时触发        │           敌方信息       机会          │             敌方渗透      三线交汇
              小冲突                                    │             玩法影响      承幕临近
              (事件)                                    │
                                                      【生存】
                                                      铜钱<30?
```

**设计原则**：

1. **出场顺序精心设计**：生存(Day 1) → 委托(Day 2) → 主线推进(Day 4) → 情报(Day 5)，每种任务在玩家最需要的时候出现
2. **不是所有体验都由任务驱动**：Day 1的酒馆老板娘互动、Day 2的小冲突、Day 3的闲聊获敌方信息——这些来自事件系统和社交系统，不需要包装成任务。任务系统负责"给玩家明确的事做"，而非"包揽所有体验"
3. **势力任务 Day 1-7 不出现**：玩家尚未加入任何势力，没有上司给你派活。要到玩家有了一定社交基础、被势力注意到之后才会开放
4. **情报委托是"准备感"核心载体**：Day 5 起幕事件后自动产生，给玩家2天时间收集线索、针对性准备
5. **任务系统反映世界状态**：敌方渗透直接影响公开委托的报酬数值（NPC生意变差→出得起的钱变少），玩家在日常循环中就能感受到世界在变化

### 2.4 敌方渗透对任务系统的影响

敌方经济渗透（详见 designDoc §12.5.1）直接影响任务系统的核心数值，让威胁从"叙事文字"变成"玩法感知"：

| 威胁度阶段 | 委托报酬变化 | 生存成本变化 | 玩家感知 |
|-----------|------------|------------|---------|
| <15 平静期 | 正常 | 正常 | 无感知 |
| 15-30 渗透期 | 报酬-20% | 食物涨价+20% | "赚得少了" |
| 30-50 挤压期 | 报酬-40%，部分委托消失 | 物价+30-50% | "东西越来越贵" |
| 50-70 垄断期 | 报酬-60%，委托大幅减少 | 部分物资断供 | 经济循环崩溃风险 |
| ≥70 封锁期 | 城外类委托不可用 | 物价暴涨 | 生存模式 |

**设计意图**：玩家不需要任何通知就能感受到"我昨天做委托赚50铜，今天只能赚40铜了"。不是"威胁度从15涨到18"这种抽象变化，而是日常循环在切实恶化。敌方渗透同时影响委托系统（报酬降低）和生存成本（物价上涨），让玩家的任务收益与敌方威胁直接挂钩。

## 3. 单日玩法循环（短期循环）

### 3.1 12时辰系统

游戏时间以12时辰自然流逝，玩家自由行动，不受回合限制。行动消耗时间，时间推进到不同时辰。

| 时辰 | 时间 | 特点 | 任务/事件触发 |
|------|------|------|-------------|
| 卯时 | 05:00-07:00 | 日出而作 | **势力任务发布（玩家无任务时）** |
| 辰时 | 07:00-09:00 | 市井开张 | **情报委托触发、告示板更新** |
| 巳时 | 09:00-11:00 | 人来人往 | 社交活动、商业交易 |
| 午时 | 11:00-13:00 | 日中之市 | **事件高发期**（概率×2.0） |
| 未时 | 13:00-15:00 | 午后小憩 | 自由行动、任务推进 |
| 申时 | 15:00-17:00 | 日落而息 | **事件触发、冲突爆发** |
| 酉时 | 17:00-19:00 | 万家灯火 | 夜间活动准备 |
| 戌时 | 19:00-21:00 | 夜市开张 | 娱乐事件、秘密活动 |
| 亥时 | 21:00-23:00 | 夜深人静 | 势力活动、夜间任务 |
| 子-丑 | 23:00-03:00 | 万籁俱寂 | 暗杀、潜入、突发事件（概率×1.5） |
| 寅时 | 03:00-05:00 | 黎明前 | 早起NPC开始活动 |

**时间控制**：
- 正常速度：时间自然流逝
- 加速：玩家选择"休息"或"等待"时，时间快速推进
- 暂停：玩家打开菜单、对话时，时间暂停

### 3.2 系统节奏与玩家自由

**核心原则：系统有节奏，玩家无限制。**

系统在特定时辰触发事件和刷新内容，但玩家可以在任何时辰做任何事——打工、闲聊、训练、休息，完全自主决定。

**系统定时触发**：

| 时辰 | 系统行为 |
|------|---------|
| 卯时 | 玩家无势力任务时，上司找玩家分配新任务（玩家在睡觉则留言） |
| 辰时 | 告示板更新（预告信息 + 新委托），情报委托NPC可能找上门 |
| 午时/申时 | 事件触发概率最高 |
| 子-丑时 | 夜间特殊事件概率×1.5 |

**玩家随时可做的事**：

- 查看告示板、接取/发布委托
- 如果发现有事件触发了，可以随时介入
- 找NPC闲聊（收集线索或纯社交）
- 打工赚钱、训练属性、购买物品
- 执行已接取的任务（情报委托、势力任务、公开委托）
- 休息（时间快进到下一个时辰）

**设计意图**：系统定时触发制造"世界在运转"的感觉，玩家自由行动保证"我在主导节奏"的体验。玩家可能早起先练武再看告示板，也可能通宵赶任务白天补觉——系统不做限制，只是错过定时触发的内容需要自己找补（比如没在卯时见上司，就得自己去找上司领任务）。

## 4. 玩家体验流

### 4.1 NPC人生节点的体验弧线

每个NPC人生节点（FateNode）包含**起承转合四个独立事件**，每个事件间隔至少2天（`min_beat_interval=2`），完整经历一个人生节点需要**7天**。每一幕触发前都有一轮「情报→准备→应对」的小循环：

```
Day 1        Day 2       Day 3        Day 4       Day 5        Day 6       Day 7
  │             │             │             │             │             │             │
  ▼             ▼             ▼             ▼             ▼             ▼             ▼
┌────┐    ┌──────────┐    ┌────┐    ┌──────────┐    ┌────┐    ┌──────────┐    ┌────┐
│ 起 │───►│ 情报+准备 │───►│ 承 │───►│ 情报+准备 │───►│ 转 │───►│ 情报+准备 │───►│ 合 │
│EMERGE│   │ 收集线索  │    │ESCALATE│ │ 针对性养成│    │CLIMAX│   │ 最后冲刺  │    │SETTLE│
│3选项 │   │ 养成属性  │    │3选项   │ │ 积累资源  │    │2选项 │   │ 善后规划  │    │2-3选项│
│低成本│   │ 积攒资源  │    │有门槛  │ │ 拉关系   │    │高消耗│   │          │    │面对后果│
└────┘    └──────────┘    └────┘    └──────────┘    └────┘    └──────────┘    └────┘
 好奇        探索           紧张        投入           抉择                      承受
 可旁观      闲聊获线索      必须站队     针对性准备      不可逆选择                 善后处理
```

**每一幕的体验小循环**：

```
情报委托 → 闲聊收集线索 → 针对性准备 → 事件触发 → 做出选择 → 结果影响下一幕
    │           │              │            │           │            │
    │           │              │            │           │            └── 后果成为下一幕的前提
    │           │              │            │           └── 准备越好，选项越多
    │           │              │            └── 门槛检验准备成果
    │           │              └── 攒钱/练武/拉关系
    │           └── 3-5个NPC身上分散着线索碎片
    └── 相关NPC发布委托，暗示下一幕方向
```

**四幕的情绪递进**：

| 幕 | 玩家情绪 | 特点 | 选项设计 |
|----|---------|------|---------|
| 起 EMERGE | 好奇 + 轻微担忧 | 低成本试探，可旁观 | 3选项，允许观望，±5~±20 |
| 承 ESCALATE | 愤怒/焦虑 + 站队欲 | 矛盾公开化，必须表态 | 3选项，禁止旁观，±10~±30 |
| 转 CLIMAX | 心痛 + 无奈 | 不可逆的二选一 | 2选项，desire vs misgiving对立，高消耗 |
| 合 SETTLE | 释然/唏嘘 + 成就感 | 面对后果，善后处理 | 2-3选项，收益可大于代价，禁止新冲突 |

### 4.2 玩家决策心理

每一幕触发前，玩家经历三个决策层次：

**信息阶段——"我该关注什么？"**
- 告示板上有预告和委托，情报委托暗示下一幕方向
- 情报委托给出方向，但不强制——玩家有自主权

**准备阶段——"我该提升什么？"**
- 线索暗示了下一幕的门槛需求（力量？金钱？关系？）
- 幕间至少3天的间隔是玩家针对性养成的窗口期
- 时间有限，不可能全部准备到位——必须取舍

**事件阶段——"我选哪个？"**
- 选项有门槛：准备充分→选择多；没准备→只有保底选项
- 选项有代价：即时消耗（金钱、关系）或触发后续任务（战斗、收集）
- 选项有后果：影响NPC命运、改变关系格局，且成为下一幕的前提条件
- **核心体验：准备越好，选择越多，结果越好——但永远不可能完美**

### 4.3 "准备感"是核心体验

区别于传统RPG"接任务→完成→交任务"的线性体验，本系统的核心体验是**"为即将到来的事情做准备"**：

- 玩家通过情报委托知道"接下来可能发生什么"
- 通过线索知道"可能需要什么"
- 通过任务和日常活动"针对性准备"
- 事件触发时验证准备成果

**有准备 vs 无准备**的体验差异：

| 状态 | 可选选项 | 体验感受 |
|------|---------|---------|
| 充分准备 | 3-4个选项可选，包括"两全其美"的隐藏选项 | 成就感、掌控感 |
| 部分准备 | 2-3个选项可选 | 有取舍但不绝望 |
| 完全没准备 | 只有保底选项（通常有负面后果） | 遗憾感，驱动下次更好地准备 |

### 4.4 四幕维度一致性——选项骨架机制

**核心原则：考验维度在起幕确定，四幕共用；玩家选择决定重心移动，但维度不变。**

一个困境的本质矛盾不会因为玩家的选择而改变类型——武力冲突始终围绕力量/金钱/智谋，不会突然变成考验魅力。因此：

1. **维度在起幕锁定**：起幕生成时，根据困境类型确定3个核心考验维度（如武力冲突→strength/money/wit），整个四幕共用这组维度
2. **门槛随幕递进**：同一维度的门槛随故事推进而升高，匹配四幕的情绪递进
3. **重心随选择移动**：玩家在每一幕的选择决定哪个维度成为下一幕的"主路"（门槛大幅升高），其他维度作为"侧路"仍然可选

**门槛递进规则**：

| 幕 | 主路门槛 | 侧路门槛 | 保底选项 | 说明 |
|---|---------|---------|---------|------|
| 起 EMERGE | 低（base） | 低（base） | 有 | 所有路线平等，试探阶段 |
| 承 ESCALATE | base × 2.0 | base × 1.5 | 有（负面后果） | 上一幕选择的路线成为主路 |
| 转 CLIMAX | base × 3.0 | base × 2.0 | 无 | 主路深入，侧路仍在但叙事上是"另辟蹊径" |
| 合 SETTLE | base × 1.5 | base × 1.0 | 有 | 善后，门槛回落 |

**"主路"由玩家选择决定**：

```
起幕：3条路线平等（strength/money/wit 都是 base 门槛）
  → 玩家选了 "武力对抗"（strength 路线）

承幕：strength 成为主路（门槛 ×2.0），money/wit 成为侧路（门槛 ×1.5）
  → 玩家这次选了 "筹钱调解"（money 路线）← 可以换路！

转幕：money 成为主路（门槛 ×3.0），strength/wit 成为侧路（门槛 ×2.0）
  → 叙事上体现为"先尝试武力，发现不行后转向金钱手段"

合幕：收尾，门槛回落，处理前面选择的后果
```

**关键体验保障**：

1. **准备永远有用**：玩家练的力量不会白费——即使换了路，strength 选项依然存在，只是不是主路
2. **选择有重量**：选择某条路会让那条路在下一幕更深入（门槛更高，叙事更丰满），但不会锁死其他路
3. **长期规划感**：情报在起幕后揭示3个维度，玩家有整个困境周期（7天）来规划，不会突然冒出新维度

**选项骨架的生成与工作流**：

骨架在生成起幕时由同一次LLM调用一并输出（起幕自身的选项不受骨架约束，起幕是低门槛试探阶段）。起幕结束后，骨架驱动情报委托的生成，并约束后续三幕的选项。

```
生成起幕（+骨架+情报素材）
    → 玩家经历起幕、做出选择（记录 committed_route）
    → 触发情报委托（线索派生自骨架，玩家收集线索、针对性准备）
    → 生成承幕（骨架约束 + 玩家当前状态快照）
    → 玩家经历承幕、做出选择（更新 committed_route）
    → [可选：简化线索更新，NPC提一句"事情变严重了"]
    → 生成转幕（骨架约束，最高门槛）
    → 玩家经历转幕、做出选择
    → 生成合幕（骨架约束放松，门槛回落）
    → 玩家经历合幕（收尾），骨架清除
```

**与情报委托的关系**：

| 时机 | 行为 | 说明 |
|------|------|------|
| 起幕生成时 | 同时输出骨架 + 情报素材 | 一次LLM调用，确保线索与骨架一一对应 |
| 起幕→承幕空白期 | **完整情报委托**（3条线索暗示3个维度） | 玩家收集、准备 |
| 承幕→转幕空白期 | 简化线索更新（NPC对话提一句"事情变严重了"） | 不需要新委托 |
| 转幕→合幕空白期 | 通常不需要 | 收尾阶段 |

核心情报只做一次完整委托，后续幕只需叙事性的门槛提示。

## 5. 任务系统设计

### 5.1 任务通用要素

所有任务共享统一要素：
- **发布人**：谁发布的任务
- **接取人**：谁来完成任务
- **发布渠道**：私下委托 vs 公开告示
- **报酬**：金钱/人情/物品/信息/关系

### 5.2 四种任务类型总览

| 任务类型 | 来源 | 触发时机 | 核心目的 | 典型报酬 |
|---------|------|---------|---------|---------|
| **情报委托** | 相关NPC | 起承转合幕前 | 提示准备方向 | 信息+关系+金钱 |
| **势力任务** | 势力上司 | 每日卯时刷新 | 提升地位资源 | 贡献+金钱+道具 |
| **公开委托** | NPC/玩家 | 随时发布 | 解决具体需求 | 约定的报酬 |
| **生存任务** | 玩家自己 | 状态阈值/事件选项 | 维持生存 | 生存本身 |

### 5.3 任务内容分类（按执行方式）

| 内容类型 | 说明 | 示例 |
|---------|------|------|
| 战斗 | 击败敌人 / 保护某人 | 击退高府打手、护送NPC |
| 收集 | 收集资源 / 物品 / 金钱 | 筹集80铜、收集木材x10 |
| 调查 | 收集情报 / 打探消息 | 打听高府真实目的 |
| 传递 | 送信 / 传话 | 把这封信送给张三 |

**执行方式与已有系统的关系**：
- 收集类任务通过已有的卡牌堆叠系统执行和校验（如"角色+树木=木材"），任务系统只负责追踪目标数量和完成判定
- 战斗类任务通过已有的战斗系统结算胜负，任务系统根据战斗结果更新完成状态
- 调查/传递类任务通过NPC对话系统完成，任务系统提供上下文（如将线索写入目标NPC的LLM上下文）

### 5.4 任务槽位限制

| 类型 | 同时最多 | 说明 |
|------|---------|------|
| 主线任务 | 1个 | QuestManager追踪，始终存在 |
| 情报委托 | 1个 | 新委托需等旧的完成或放弃 |
| 势力任务 | 1个 | 上司同时只派1个活 |
| 公开委托 | 不限 | 但受时间精力制约 |
| 生存任务 | 1个 | 状态恢复后自动消失 |

### 5.5 情报委托

**作用**：起幕事件的余韵对话中，反派/冲突方会自然地预告下一步威胁（如"等我舅舅来收拾你！"）。当事NPC听到后心生担忧，委托玩家去打听情况。线索暗示下一幕的能力/资源需求，让玩家有方向地准备。

**触发方式**：
- **不是**随机NPC辰时找上门委托
- **而是**起幕余韵结束后，当事NPC（FateNode的主角NPC）基于事件中听到的威胁，自然地请求玩家帮忙打听
- 发布人 = 当事NPC（如张铁匠），不是旁观者

**核心机制**：
- 每个委托需要收集3条线索碎片
- 设计委托时，将线索预分配到3-5个目标NPC身上，写入其LLM上下文
- **每条线索暗示不同的准备方向**：3条线索应分别指向下一幕的不同选项路径（如武力/金钱/调查），让玩家收集完后能看到多种可能性，自主选择投入哪条路
- 非目标NPC不持有线索，但打探时可能给出背景信息或"不清楚"
- 凑齐3条线索后，触发玩家内心总结，以叙事语言并列呈现各条路的可能性，不偏向任何一条
- 回复委托发布人结算报酬

**选项骨架（ChoiceScaffold）——线索与选项的一致性保障**：

情报委托的线索和后续事件的选项必须一一对应。为此，两者由同一次LLM调用生成：

```
生成起幕时，LLM 一次性输出：

① 起幕事件内容 + 选项（照旧，低门槛，自由生成）

② 选项骨架 scaffold（新增输出，存入 NPCDilemmaSeed）:
   - 路线A: {attr: "strength", base_threshold: 20, label: "武力对抗"}
   - 路线B: {attr: "money",    base_threshold: 30, label: "金钱调解"}
   - 路线C: {attr: "wit",      base_threshold: 15, label: "暗中调查"}
   - 保底:  {attr: null,                           label: "妥协退让"}

③ 情报委托素材（新增输出，用于创建 IntelQuest）:
   - 线索1 → 对应路线A: "对方是练家子"（暗示 strength）
   - 线索2 → 对应路线B: "拿钱办差的"（暗示 money）
   - 线索3 → 对应路线C: "背后有人指使"（暗示 wit）
   - 建议的线索持有NPC列表
```

**为什么必须同时生成**：如果线索和选项分两次LLM调用生成，线索可能暗示"需要力量"，但后续事件的LLM却生成了"需要魅力"的选项——线索与选项脱节，玩家的准备白费。同时生成确保线索从选项骨架派生，天然一致。

**骨架的生命周期**：
1. **起幕生成时**创建：与起幕同一次LLM调用，确定3个核心维度和基础门槛
2. **起幕选择后**记录重心：`seed.player_committed_route` = 玩家选择对应的路线
3. **承幕/转幕生成时**注入约束：骨架作为硬约束写入LLM prompt，门槛按 §4.4 规则递进（详见 §6.10）
4. **每幕选择后**更新重心：玩家可以换路，committed_route 随之更新
5. **合幕结束后**清除：困境完结，骨架失效

**打探线索交互**：

玩家持有情报委托期间，与NPC的聊天界面中输入框上方出现「打探线索」快捷回复按钮（复用ChatUI的quick_replies机制）：

```
┌─────────────────────────────────────┐
│ 与 张铁匠 对话                  [×] │
├─────────────────────────────────────┤
│                                     │
│  （对话消息区）                      │
│                                     │
├─────────────────────────────────────┤
│ [打探线索]                           │
├─────────────────────────────────────┤
│ [输入消息...                ] [发送] │
└─────────────────────────────────────┘
```

- **点击「打探线索」**：等同于玩家发送一条预设消息（如"对了，最近镇上那些外地人你知道什么吗？"），NPC基于其LLM上下文中的线索内容自然回复
  - 目标NPC：回复中自然透露线索碎片，系统判定获得线索进度+1
  - 非目标NPC：给出"不太清楚"或无关背景信息，不增加进度
- **无情报委托时**：「打探线索」按钮不显示，界面与当前一致
- **已打探过的NPC**：按钮变灰显示"已打探"，不可重复点击

**情报委托的触发时机**：

| 时机 | 类型 | 委托示例 | 说明 |
|------|------|---------|------|
| 起幕结束后 | 完整情报委托（3条线索） | "打听高府的来头" | 线索派生自骨架，暗示3个核心维度。起幕→承幕间的2天空白期执行 |
| 承幕→转幕空白期 | 简化线索更新 | NPC说"高府又加派了人手" | 不需要新委托，NPC对话自然提及门槛升高 |
| 转幕→合幕空白期 | 通常不需要 | — | 合幕是收尾阶段，门槛回落 |

**线索收集流程**：
```
【事件余韵】
起幕事件结束，余韵对话中：
  一只耳（撂狠话）："哼，等我舅舅黄三爷来了，有你好看的！"
  张铁匠（在旁边听到，拉住玩家）："兄弟，黄三爷这个人...你能帮我打听打听吗？"
→ 触发情报委托（发布人=张铁匠），聊天界面出现「打探线索」按钮

【收集线索】
找目标NPC对话 → 点击「打探线索」 → NPC自然透露线索碎片 → 进度+1
找非目标NPC对话 → 点击「打探线索」 → NPC说不清楚 / 给出无关背景信息

【凑齐线索】
3/3线索收集完毕 → 触发玩家内心总结（叙事语言并列呈现各条路的可能性）
例："黄三爷当过镖师，拳脚了得...不过听说贪财，给够银子也许能打发，
     他跟县衙有旧怨，找王捕头说不定有别的办法。"

【交付委托】
回到张铁匠身边对话 → 结算报酬（金钱/关系）
→ 张铁匠根据玩家当前属性给出模糊评价，暗示哪些维度够用、哪些还差得远
  （系统读取玩家属性与下一幕各选项门槛的差距，转化为NPC口吻的叙事建议）
```

**余韵对话中的叙事钩子**：

起幕的 choice_dialogues（选项后续对话）中必须包含对下一幕威胁的自然预告。这个预告由LLM在生成起幕时一并输出（与骨架同一次调用），确保钩子内容与骨架维度对应：

```
choice_dialogues 中的叙事钩子示例：

武力冲突型：反派撂狠话 → "等我舅舅来！" / "你等着，这事没完！"
经济困境型：债主施压 → "三天后还不上，铺子就归我了！"
人际纠纷型：关系破裂 → "你站他那边？行，咱们走着瞧！"

→ 当事NPC听到后自然委托玩家打听
→ 钩子的内容暗示威胁方向，但不暴露具体门槛（具体门槛通过线索获取）
```

**不同困境类型暗示不同准备方向**：

每种困境类型有其主要矛盾，但线索设计时应覆盖多条应对路径，不局限于单一维度：

| 困境类型 | 线索应覆盖的方向 | 示例（3条线索分别暗示） |
|---------|----------------|----------------------|
| 经济困境 | 金钱 / 关系 / 智力 | "欠了大笔钱" / "债主和谁关系好" / "这笔账有蹊跷" |
| 武力冲突 | 力量 / 金钱 / 调查 | "对方是练家子" / "拿钱办差的" / "背后有人指使" |
| 人际纠纷 | 魅力 / 金钱 / 关系网 | "需要人说情" / "送礼能缓和" / "谁和两边都熟" |
| 知识谜题 | 智力 / 物品 / 关系 | "古籍里有记载" / "需要特殊材料" / "只有某人懂这个" |
| 势力斗争 | 声望 / 金钱 / 情报 | "需要有分量的人出面" / "打通关系要花钱" / "对方有把柄" |

**设计约束**：
- 同时最多1个情报委托
- 不完成无惩罚——事件照常触发，只是玩家缺少准备信息
- 放弃委托：发布人好感仅微降（-5）

### 5.5.1 信息作为战略资源（designDoc §十一）

情报委托系统中，信息不是免费的背景文本，而是有成本、有价值、有时效的战略资源：

| 信息属性 | 对情报委托的影响 | 示例 |
|---------|----------------|------|
| **获取成本** | 线索需要投入时间、铜钱或人情才能获得 | 去酒馆打听消耗时间+铜钱 |
| **使用价值** | 线索可解锁更好的事件选项 | 知道高府把柄→解锁CLIMAX第3选项 |
| **时效性** | 部分线索有时间窗口，过期失效 | "青龙帮明晚动手"→明天之后无效 |
| **排他性** | 玩家独有的信息可以选择透露给谁 | 只有你知道真相→选择告诉谁影响局势 |

**选择性透露**：当玩家持有排他信息时，后续事件选项中动态增加"告诉谁"的分支：
- 告诉当事人 → 当事人好感+，但信息扩散（涟漪传播）
- 告诉第三方 → 借力，走间接路线
- 保密 → 保留信息优势，但当事人可能因不知情而受害

这些选项由AI叙事引擎在生成事件时，自动检查玩家的已知信息列表并纳入选项生成。

**信息拼图**：不同NPC掌握事实的不同碎片（通过感知过滤器决定），玩家从多个NPC处收集碎片后，事件系统检测到关键信息组合时可解锁新选项。与卡牌堆叠系统配合：线索卡+线索卡 = 更完整的情报（通过 `recipes.csv` 配方定义）。

### 5.6 势力任务

**作用**：玩家加入势力后，上司发布有期限的任务，用于提升势力贡献度和职级。势力是玩家对抗仇敌的组织化力量——职级越高，终局时能调动的人手、资源和情报越多，选项和胜算越大。

**势力结构**：

```
势力领袖 (LEADER, rank 5)
    └── 头目 (MANAGER, rank 4)
        └── 干部 (SENIOR, rank 3)
            └── 成员 (MEMBER, rank 2)
                └── 新人 (ROOKIE, rank 1)
```

**加入势力**：
- 主动申请：与势力成员好感度≥30 或完成入门任务，领袖批准后获得rank 1，分配直接上司
- 被邀请加入：对势力有大贡献/与领袖关系极好，跳过考核直接rank 2

**自创势力**：
- 条件：声望≥100 + 资金≥1000铜 + 至少2名NPC愿意追随（好感度≥70）
- 流程：选择势力类型（士/农/工/商/学/兵/游/匪）→ 命名 → 选择据点 → 邀请追随者
- 特点：玩家是领袖，没有上司；可下达任务给成员；可扩张势力范围

**任务发布与接取**：
- 玩家身上无势力任务时，上司在卯时（05:00-07:00）主动找玩家分配新任务
- 任务有期限（1-7天不等），期限内完成即可
- 如果玩家在睡觉，上司会留言等待
- 玩家可选择接取或拒绝（拒绝影响评价）
- 最多同时接取1个势力任务

**上司分配任务的对话形式**：
```
上司NPC走到玩家面前：
"小李，有件事需要你去办..."

对话选项：
[接下任务]
[询问详情]
[婉言拒绝]（可能影响评价）
```

**任务类型**：

任务内容随主线威胁度阶段变化，由AI导演调整势力任务池：

| 威胁度阶段 | 任务倾向 | 期限 | 示例 | 奖励 |
|-----------|---------|------|------|------|
| <20 平静期 | 日常经营 | 1-2天 | 收集木材x10、巡逻镇东、送货 | 贡献+10，铜钱+50 |
| 20-40 暗流期 | 调查侦察 | 2-3天 | 打探陌生人来历、监视可疑活动 | 贡献+20，铜钱+80 |
| 40-60 风暴前 | 拉拢备战 | 3-5天 | 拉拢中立NPC、对抗敌对势力渗透 | 贡献+50，特殊道具 |
| 60+ 正面对抗 | 战争动员 | 5-7天 | 囤积物资、修筑防御、招募盟友 | 贡献+100，晋升机会 |
| 达到晋升条件 | 晋升考核 | 3天 | 单挑某高手、完成关键委托 | 地位提升，解锁新权限 |

**晋升机制**：完成任务获得功勋(faction_fame) → 累积达标触发晋升考核 → 职级提升 → 解锁更多任务类型、可下达任务给下级、获得势力资源分成

**势力任务面板**：

```
┌─────────────────────────────────────┐
│           势力：黑风寨               │
├─────────────────────────────────────┤
│ 我的地位：普通成员                   │
│ 贡献值：120/500（晋升需要500）       │
├─────────────────────────────────────┤
│ 【当前任务】                         │
│ • 收集木材x10 [进度: 3/10]          │
│   奖励：贡献+10，铜钱+50             │
│ • 巡逻镇东 [未完成]     
│   限时：3天                          │
│   奖励：贡献+10，铜钱+30     
        │
├─────────────────────────────────────┤
```

### 5.7 公开委托

**作用**：NPC和玩家都可以在江湖告示板上发布/接取委托，解决具体需求。

**发布渠道**：

| 渠道 | 可见性 | 报酬要求 | 特点 |
|------|--------|----------|------|
| 江湖告示板 | 所有人可见 | 必须写明报酬 | 陌生人之间，需明确条件 |
| 私下委托 | 仅双方可见 | 可以不写（人情交换） | 熟人之间，看交情 |

**江湖告示板**：

告示板是玩家获取信息和任务的统一入口，包含预告信息（AI导演生成，被动阅读）和委托任务（NPC/玩家发布，主动接取）。

```
┌─────────────────────────────────────────────────────────────────┐
│                       江湖告示板                                 │
├─────────────────────────────────────────────────────────────────┤
│ 【公告】近日有外地客商入镇，望各铺面注意来路不明之人。          │
│   —— 镇衙门                                                     │
├─────────────────────────────────────────────────────────────────┤
│ 【悬赏】送货到城外，报酬50铜                           [接取]   │
│   发布人：李掌柜 | 剩余3天                                       │
├─────────────────────────────────────────────────────────────────┤
│ 【求助】找人帮忙修屋顶，报酬20铜                       [接取]   │
│   发布人：张大婶 | 剩余2天                                       │
├─────────────────────────────────────────────────────────────────┤
│ [+发布我的委托]                                                  │
└─────────────────────────────────────────────────────────────────┘
```

告示板位置：主城广场（最繁忙）、各势力据点、村镇入口

**玩家发布委托流程**：
1. 走到告示板，选择"发布委托"
2. 填写标题、描述、报酬类型/数量、截止时间、是否匿名（额外收费）
3. 支付报酬5%的手续费
4. 等待NPC接取

**玩家发布委托的典型场景**：

| 场景 | 委托内容 | 报酬 |
|------|---------|------|
| 需要某样物品但找不到 | "收购铁矿石30块" | 60铜 |
| 需要护送但无暇亲自去 | "护送商队到城外" | 100铜 |
| 想打听情报但不方便亲自行动 | "打听商会最近的动静" | 80铜 |
| 需要人手帮忙 | "帮忙清理仓库" | 40铜 |

**私下委托**：玩家直接与NPC对话发起，不需要手续费，可以不写报酬（NPC看交情决定是否帮忙），只有目标NPC能看到。

**NPC发布委托**：NPC根据自身需求金字塔（见 designDoc 第六节）的当前未满足层级驱动发布：

| 未满足层级 | 发布倾向 | 示例 |
|-----------|---------|------|
| 生存层 | 觅食/求助类委托 | "收购粮食x5，报酬30铜" |
| 安全层 | 护卫/调查类委托 | "有人威胁我，帮我查查来路" |
| 归属/尊重层 | 社交/声望类委托 | "帮我送份礼给张老板" |
| 需求已满足 | 按职业默认需求发布 | 商人→"送货"、铁匠→"采购铁矿" |

富裕NPC报酬高，贫穷NPC报酬低。需求越紧迫，NPC愿意开出的报酬越高。

**NPC接取玩家委托的决策因素**：
- 能力匹配：做不了的直接拒绝
- 报酬吸引力：金钱或人情的价值
- 时间充裕度：正忙的倾向拒绝
- 当前需求层级：生存/安全未满足的NPC优先接取能满足其需求的委托（如缺钱的NPC更愿意接高报酬委托，受威胁的NPC更愿意接能获得保护关系的委托）
- 性格倾向：贪财的更容易接、懒惰的不爱接、勇敢的不怕危险任务
- 与发布人的关系（非匿名时）：帮朋友，不帮讨厌的人

**结算与风险**：
- 完成后自动结算报酬，双方好感+5
- 超时未完成：自动取消，退还报酬（扣手续费），接取人信誉下降
- 发布人报酬不足：委托失败，信誉下降

**敌方渗透对委托的影响**（详见 §2.4）：
- NPC收入下降时，发布的委托报酬自然降低（NPC生意变差→出得起的钱变少）
- 部分NPC商铺被敌方控制后，该NPC不再发布委托
- 城外类委托在高威胁度（≥70）时不可用（通道被封锁）
- 玩家通过日常做委托就能感受到世界在变化，不需要额外的通知系统

### 5.8 生存任务

**作用**：当玩家状态低于阈值时自动触发，以内心独白形式呈现，维持生存压力感。生存任务不是纯提示——它与 designDoc 定义的数值惩罚同步触发，是压力的玩法出口。

**状态阈值触发**：

| 状态 | 阈值 | 生成的任务 | 同步的gameplay惩罚（designDoc已定义） |
|------|------|-----------|--------------------------------------|
| 饱食度 | < 30 | "得找点吃的" | 行动效率×0.7，每日扣HP |
| 寒冷值 | > 60 | "太冷了，得弄件衣服" | ≥80时每日扣HP |
| 铜钱 | < 30 | "没钱了，得去赚点" | 无法选择需要金钱的事件选项 |
| HP | < 30 | "伤得不轻，得养养" | 接近死亡，战斗/冒险选项风险极高 |

生存任务的意义在于：当数值惩罚生效时（如屏幕边缘黑影、角色变慢），玩家在目标面板上能看到具体的行动指引，将"我状态很差"转化为"我该去做什么"。

**事件选项触发**：

当玩家在事件中选择了对抗性选项后，可能触发"必须完成"的生存任务。例如：

```
玩家选择："谁敢动张大哥的铺子，先过我这关！"
→ 高府打手不肯罢休
→ 触发生存任务："击退高府打手"

为什么算"玩家自己发布的任务"：
├── 玩家主动选择了武力对抗
├── 选择就意味着承担后果
├── 不完成自己会受伤害
└── 发布人：PLAYER
```

**设计约束**：
- 自动触发，不需要NPC发布
- 状态恢复后自动完成，有明确UI反馈（"嗯，吃饱了，舒服多了"）
- 只在状态真正危险时触发，避免成为噪音
- 与时辰无关，随时可能触发

### 5.8a 主线任务

**作用**：主线任务贯穿开局前10天，为玩家提供长期方向感。不同于生存任务的即时压力，主线任务是"我接下来该往哪走"的牵引力。

**触发时机**：Day 1 亥时（21:00），通过玩家内心独白自然触发，不是系统强塞：

```
睡前内心独白：
"总算活过了今天...可我不能一直这样。
 那些人迟早会找到这里，我得在这座城站稳脚跟。"

→ 主线任务："在城中站稳脚跟"
```

**设计意图**：白天玩家忙着活命，没有余力想长远。只有晚上躺下来，才自然地开始想"接下来怎么办"。这让主线任务的出现是情感驱动的。

**阶段推进**（详见 designDoc §12.2.2）：

| 阶段 | 目标 | 完成条件 | 大约时间 |
|------|------|---------|---------|
| 阶段1 | 活下来 | 找到食物和住处 | Day 1-2 |
| 阶段2 | 有收入 | 稳定的经济来源 | Day 2-4 |
| 阶段3 | 有根基 | 至少1个NPC好感≥50 | Day 4-10 |
| 阶段4 | 有势力 | 加入或创建势力 | Day 10+ |

每个阶段完成时给予成就感反馈，同时自然过渡到仇敌威胁主线。阶段3完成时，仇敌的渗透行动开始产生可感知的影响——玩家刚站稳脚跟，脚下的地就开始被抽走。

### 5.9 玩家目标面板

**设计原则**：轻量化，不是任务清单，而是"当前关注"。

```
┌─────────────────────────────────────┐
│ 当前关注                             │
├─────────────────────────────────────┤
│ 仇敌 [威胁度 32/100]                 │
│   • 有人在暗中打听我的下落...          │
├─────────────────────────────────────┤
│ 我的状态                             │
│   • 肚子饿了，得找点吃的              │
├─────────────────────────────────────┤
│ 别人的托付                           │
│   • 李大婶：问问张铁匠陌生人长相 (1/3)│
├─────────────────────────────────────┤
│ 势力任务                             │
│   • [黑风寨] 收集木材x10 (3/10)      │

```

**约束**：最多同时显示1个主线任务 + 1个情报委托 + 1个生存任务 + 1个势力任务。任务描述要有叙事感，不是机械的目标。

## 6. 事件系统与任务系统协同

### 6.1 NPC人生困境事件（起承转合四幕）

AI导演随机触发NPC的人生困境事件，每个困境围绕NPC的desire vs misgiving展开，遵循"起承转合"四幕结构。

| 幕 | 设计目标 | 选项特点 | 数值变动幅度 |
|---|---------|---------|-------------|
| **起 EMERGE** | 低成本试探，了解局势、建立立场 | 3选项，门槛低，主要影响关系 | ±5~±15 |
| **承 ESCALATE** | 矛盾升级，必须展现能力或付出代价 | 3-4选项，有硬性门槛，必须站队 | ±10~±25 |
| **转 CLIMAX** | 高消耗抉择，不可逆选择 | 2选项+可解锁第3，高成本高回报 | ±20~±40 |
| **合 SETTLE** | 面对后果，善后处理 | 2-3选项，动态生成，影响口碑 | ±10~±30 |

### 6.2 选项字段规范

每个选项包含以下字段：

| 字段 | 含义 | 何时结算 |
|-----|------|---------|
| `requirement` | 门槛条件 | 选择前检查，不满足则灰显不可选 |
| `cost` | 代价/损失 | 剧情对话结束后结算 |
| `effect` | 正面收益 | 剧情对话结束后结算 |
| `transfer` | 资源转移（物质守恒） | 剧情对话结束后结算 |
| `triggers_task` | 触发后续任务（**新增**） | 选择后生成新任务，任务完成后再结算 |

#### 字段格式

**requirement**：`actor:attribute:compare_symbol:needvalue`
- 示例：`PLAYER:charm:>=:50`、`1001:affinity_to_player:>=:20`、`ITEM:高府把柄:>=:1`
- 多个条件用分号隔开
- requirement中的needvalue必须与cost/transfer中的实际消耗数值一致

**cost**（只用于代价/损失，禁止金钱！金钱用transfer）：
- 格式：`actor_id:attribute:changevalue`，多个用分号隔开
- 可用类型：`PLAYER:fame:-N`（声望损失）、`PLAYER:strength:-N`（能力下降）、`NPC_ID:affinity_to_player:-N`（好感降低）
- 示例：`PLAYER:fame:-10;1001:affinity_to_player:-5`

**effect**（只用于正面收益，禁止放任何负面效果！）：
- 格式：`actor_id:attribute:changevalue`，多个用分号隔开
- 示例：`1001:affinity_to_player:10;PLAYER:wit:3`
- NPC情绪变化：`actor_id:emotion:EMOTION值`（如`1001:emotion:HAPPY`）

**transfer**（金钱/物品转移，满足进出平衡）：
- 格式：`from_actor->to_actor:attr:value`
- 示例：`PLAYER->1001:money:30`（玩家给NPC 30金钱）
- 多个转移用分号隔开

**triggers_task**（**新增字段**，触发后续任务）：

```yaml
triggers_task:
  task_type: "战斗/收集/调查/传递"
  source_type: "生存任务/情报委托"
  title: "任务标题"
  publisher: "PLAYER 或 NPC_ID"
  description: "任务描述"
```

#### 选项设计核心规则

1. **每个选项必须有代价**：cost字段禁止为null（代价可以很低，但不能没有）
2. **正负分开**：正面收益放effect，负面代价放cost，泾渭分明
3. **代价守恒**：effect正面收益的绝对值与cost负面代价的绝对值比例不得超过2:1
4. **代价逻辑一致**：代价必须与选项做法在逻辑上一致（做好事不该扣声望，仗势欺人才扣声望）
5. **禁止重复属性**：cost和effect禁止包含相同的属性（不能自相抵消）

#### 两种结算方式

1. **即时结算**：`cost`/`effect`/`transfer` 有值，`triggers_task` 为空
   - 剧情对话结束后直接结算
   - 例：劝张妥协 → cost: 1001:affinity_to_player:-15, effect: 1003:affinity_to_player:10

2. **触发后续任务**：`cost`/`effect`/`transfer` 为空，`triggers_task` 有值
   - 生成新任务，任务完成后再结算最终结果
   - 例：武力对抗 → triggers_task: 战斗任务"击退高府打手"

**发布人判定**：
- 玩家主动选择的对抗/挑战 → source_type: 生存任务，publisher: PLAYER
- 事件当事人请求帮助 → source_type: 情报委托，publisher: 当事NPC_ID

### 6.3 选项选择后的剧情流程

```
1. 开场对话 intro（8-10句）
   场景开幕 → 冲突展示 → 各方反应 → 氛围升级 → 弹出选择界面

2. 玩家做出选择

3. 选项后续对话 choice_dialogues（5-7句）
   玩家登场 → 各方反应 → 交锋推进 → 余韵收尾

4. 结算或触发后续
   即时结算：结算 cost/effect/transfer
   触发任务：生成后续任务 → 任务完成后再结算最终结果
```

选项选择后**不会立刻中断剧情**，而是先展示现场各方反应，对话结束后才进行结算或触发后续任务。

### 6.4 各幕设计原则与示例

**以"张铁匠困境"为贯穿示例**：张铁匠女儿病重需要100铜买药，高府趁机逼迫收购铁铺。

> **骨架注释**：本困境类型为"武力冲突"，起幕生成时同步输出选项骨架：
> scaffold = {strength(base:20), money(base:30), wit(base:15), 保底}。
> 起幕选项自由生成不受骨架约束；承幕起骨架生效，选项的 requirement 维度必须与骨架对应。

---

**起（EMERGE）：低成本试探**

门槛低、成本低，主要影响社交关系。让玩家了解局势并建立情感连接。

```
张铁匠："兄弟，我女儿病重，需要100铜买药..."

选项A [主动帮助]："张大哥别急，我帮你想想办法"
  requirement: null
  cost: PLAYER:fame:-5
  effect: 1001:affinity_to_player:15
  transfer: null
  triggers_task: null
  → 低成本承诺，关系收益高，但后续可能需要投入资源

选项B [观望打听]："我先去药铺问问药价..."
  requirement: null
  cost: PLAYER:fame:-3
  effect: 1001:affinity_to_player:5
  transfer: null
  triggers_task: null
```

### 6.5 四幕的核心设计原则

1. **每个选项都是多维度的**：可以同时有门槛、消耗、收益，不是"每幕只考验一种维度"
2. **门槛设计创造养成动力**：玩家看到"力量≥45"的选项就会想去提升力量
3. **消耗设计创造资源压力**：权衡"现在付出" vs "未来收益"
4. **不同选项考验不同维度**：让玩家有选择养成方向的自由

### 6.6 势力任务与人生困境事件的交叉

势力任务和人生困境事件是独立系统，但通过两种方式自然交织：

**交织一：势力成员的困境 = 势力任务**

势力成员本身是NPC，他们也会触发人生困境。当成员陷入困境时，上司可能直接将"帮助成员"作为势力任务派给玩家：

```
张铁匠（黑风寨成员）触发人生困境 →
上司派势力任务："去帮张铁匠解决高府的麻烦"
→ 势力任务和NPC事件合一，完成事件 = 完成势力任务
→ 同时获得：事件选择结果 + 势力贡献奖励
```

此时势力任务不再是孤立的"打工"，而是玩家参与事件的另一条入口。

**交织二：势力利益与个人关系的张力**

NPC事件中的选项可能与势力利益冲突，迫使玩家在个人关系和势力立场之间取舍：

```
场景：高府是黑风寨的合作方，张铁匠（非成员）被高府施压。

帮张铁匠对抗高府 → 张铁匠关系+50，但势力贡献-30、上司好感-20
顺从势力利益不介入 → 势力贡献+20，但张铁匠关系-30

→ 玩家需要权衡：一个铁杆盟友 vs 势力内的地位
```

### 6.7 AI导演如何驱动任务生成

AI导演的宏观/微观双层架构（见 designDoc 5.4节）通过三个接口影响任务系统：

**接口一：导演意图 → 情报委托节奏**

宏观层输出的"导演意图"（施压/缓解/维持）影响情报委托的生成时机：

| 导演意图 | 对情报委托的影响 |
|---------|----------------|
| 施压 | 情报委托更早触发（幕前2天而非1天），线索指向更高门槛的选项 |
| 缓解 | 情报委托可延迟触发，线索更多指向低成本选项 |
| 维持 | 正常节奏触发 |

导演的"连续施压≤3天"保护规则生效时，不会在缓解日额外叠加新情报委托或提高势力任务难度。

**接口二：种子池权重 → 势力任务倾向**

5.6节的威胁度阶段表已定义了任务类型的基础分布。AI导演的种子池权重在此基础上做动态调整：
- 种子池中"社会动荡"权重×2.0时，势力任务倾向调查侦察类
- 种子池中"日常温情"权重提高时，势力任务倾向日常经营类

**接口三：微观层回响 → triggers_task 内容**

微观层的"代价回响"机制影响事件选项触发的后续任务：玩家之前的行动会让后续任务有针对性变化。

```
例：Day 12 玩家调查了青龙帮
→ 微观层标记"代价回响"
→ Day 13 张铁匠事件的选项中，triggers_task 难度上调
   （青龙帮因被调查而加派人手 → 战斗任务敌人更强）
```

### 6.8 事件结果的涟漪与任务联动

事件结果通过涟漪系统（见 designDoc 5.7节）传播后，可能反向触发新任务：

**涟漪 → NPC发布新委托**

事件结果改变周围NPC的态度和需求，态度变化足够大的NPC可能因此发布新的公开委托：

```
事件结果：玩家帮张铁匠对抗高府
  → 涟漪传播：周围NPC不安感+3
  → 赵掌柜（不安感超过阈值）发布委托："找人帮忙看店三天，报酬40铜"
  → 王捕头发布委托："打听外地人的来路，报酬60铜"
```

**群体行为涌现 → 势力任务响应**

当涟漪传播触发群体行为（designDoc 已定义：群体规模≥3 且平均压力≥阈值）时，势力上司可能据此派发新的势力任务：

```
群体行为：镇上多个NPC因外来势力威胁而自发组织巡逻
  → 上司派势力任务："协助镇民组织夜间巡逻"
  → 或对立势力上司派任务："阻止民间自发武装"
```

任务系统不参与涟漪传播的计算，只作为涟漪结果的下游响应者——涟漪系统输出NPC态度变化和群体行为事件，任务系统据此生成对应的委托或势力任务。

### 6.9 共享叙事记忆与任务联动

世界事实库（详见 designDoc 5.8节）是系统叙事状态的唯一权威来源。任务系统既是事实库的写入者，也是消费者。

**任务系统写入事实库**：
- 任务完成/失败的结果（如"玩家完成了筹集80铜的委托"）
- 玩家在任务中的具体行为和选择（如"玩家选择武力对抗而非调解"）
- 任务引发的关系变化（如"张铁匠好感+15"）
- 生存任务触发/消失记录（如"玩家饥饿→进食→恢复"）

**任务系统读取事实库**：
- **情报委托线索**：NPC通过感知过滤器后获知的信息，决定其能透露的线索深度。亲眼所见的NPC能给出精确线索；间接听闻的NPC只能给出模糊方向
- **势力任务分配**：上司基于已知的世界状态分配任务——上司不知道的事不会成为任务内容
- **NPC委托发布**：NPC根据自己感知到的威胁/需求发布委托，而非全局信息

**感知过滤器对任务的影响**：

| 场景 | 无感知过滤（全知） | 有感知过滤（合理认知） |
|------|-------------------|----------------------|
| 玩家暗中调查青龙帮 | 所有NPC都知道玩家在调查，青龙帮立刻报复 | 只有目击者和其社交圈知道，青龙帮需要通过线索才能确认是谁 |
| 张铁匠被威胁 | 全镇NPC立刻发布求助委托 | 只有邻居和亲友知道，逐步扩散后才有更多人发布相关委托 |
| 玩家帮赵掌柜修门 | 所有NPC好感+5 | 在场NPC好感+5，其他NPC通过听闻后续好感变化更小且延迟 |
| 情报委托打探线索 | 随便找谁都能获得线索 | 只有与事件有合理关联的NPC才持有线索，且信息深度取决于感知途径 |

**感知过滤与任务系统的交互流程**：

```
事件发生 → 写入世界事实库
    ↓
涟漪系统传播 → 确定哪些NPC知道此事（传播范围）
    ↓
感知过滤器 → 确定每个NPC知道的细节程度（信息深度）
    ↓
任务系统消费：
├── 情报委托：根据NPC感知深度决定线索质量
├── 势力任务：上司根据已知信息分配任务
├── NPC委托：NPC根据感知到的需求/威胁发布委托
└── 生存任务：不受感知过滤影响（玩家自身状态）
```

**设计约束**：
- 感知过滤是"信息获取的边界"，不是"信息传播的速度"——速度由涟漪系统控制
- NPC的感知范围应随好感度和社交网络自然扩展——忠诚的NPC会主动分享信息
- 公共知识不需要感知过滤——涟漪传播超过阈值的事件自动成为全镇共知

### 6.10 选项骨架与LLM生成约束

选项骨架（ChoiceScaffold）是情报委托线索与事件选项之间的桥梁。它在起幕生成时创建（§5.5），在后续幕生成时作为硬约束注入LLM prompt，确保LLM生成的选项与之前给玩家的线索一一对应。

**骨架约束如何注入LLM prompt**：

生成承幕/转幕/合幕时，在现有的LLM prompt（玩家状态、NPC信息、phase指令等）基础上，新增一段骨架约束：

```
## 选项设计约束（基于选项骨架，必须遵守）

本困境的核心考验维度已确定，生成的选项必须与以下路线对应：

- 路线A「武力对抗」: requirement 必须包含 PLAYER:strength:>=:{计算后门槛}
- 路线B「金钱调解」: requirement 必须包含 PLAYER:money:>=:{计算后门槛}
- 路线C「暗中调查」: requirement 必须包含 PLAYER:wit:>=:{计算后门槛}
- 保底「妥协退让」: requirement 为 null（承幕有，转幕无）

玩家上一幕选择了「{committed_route}」路线，这是当前主路。
主路的选项在叙事上应该是该路线的自然深入和升级。
侧路的选项在叙事上应该是"换一种方式解决"。

玩家当前状态：strength={X}, money={Y}, wit={Z}, charm={W}
```

**门槛的计算方式**：

门槛不写死在骨架里，而是根据当前幕和主/侧路关系动态计算：

```python
def calculate_threshold(base_threshold, phase, is_main_route):
    multipliers = {
        "EMERGE":   (1.0, 1.0),   # 起幕：主路=1.0, 侧路=1.0（不区分）
        "ESCALATE": (2.0, 1.5),   # 承幕：主路=2.0, 侧路=1.5
        "CLIMAX":   (3.0, 2.0),   # 转幕：主路=3.0, 侧路=2.0
        "SETTLE":   (1.5, 1.0),   # 合幕：主路=1.5, 侧路=1.0
    }
    main_mult, side_mult = multipliers[phase]
    mult = main_mult if is_main_route else side_mult
    return int(base_threshold * mult)
```

**committed_route 的更新逻辑**：

每幕结束后，根据玩家选择的选项对应的路线更新 `seed.player_committed_route`：
- 选了 strength 路线的选项 → committed_route = "strength"
- 选了保底选项 → committed_route 不变（保底不算选择路线）
- 玩家可以在不同幕之间换路，系统不限制

**LLM 的自由度与约束边界**：

骨架约束的是**选项的 requirement 字段**（必须对应指定维度），不约束：
- 选项的叙事文本（LLM自由创作，体现当前幕的故事发展）
- cost/effect/transfer 的具体数值（LLM根据剧情合理设计）
- consequence_preview（LLM根据玩家状态和门槛差距自由描述）
- 选项间的关系张力（LLM根据 desire vs misgiving 自由设计对立感）

这样骨架确保"维度一致性"，LLM确保"叙事丰富性"，两者各司其职。

**完整示例——张铁匠困境四幕骨架流转**：

```
第1步：生成起幕（困境类型=武力冲突）
  LLM 输出：
    起幕事件 + 选项（低门槛，自由生成）
    scaffold = {
      routes: [
        {attr: "strength", base: 20, label: "武力对抗"},
        {attr: "money",    base: 30, label: "金钱调解"},
        {attr: "wit",      base: 15, label: "暗中调查"}
      ],
      fallback: {label: "妥协退让"}
    }
    intel_material = {
      clues: ["对方是练家子", "拿钱办差的", "背后有人指使"],
      target_npcs: ["张铁匠", "赵掌柜", "李大夫"]
    }

第2步：玩家经历起幕，选了"教训一只耳"
  余韵对话：一只耳撂话"等我舅舅黄三爷来！"
  张铁匠："兄弟，黄三爷...你能帮我打听打听吗？"
  → committed_route = "strength"（选项对应 strength 路线）
  → 触发情报委托（发布人=张铁匠）

第3步：玩家收集3条线索
  赵掌柜："黄三爷当过镖师，拳脚了得"  → 线索1 → strength
  李大婶："那人贪财，给够银子什么事都好说" → 线索2 → money
  王捕头："黄三爷跟县衙有旧怨"          → 线索3 → wit
  → 回到张铁匠交付，张铁匠根据玩家状态给出模糊评价
  → 玩家花2天赚钱，money: 50→120

第4步：生成承幕
  prompt 注入骨架约束：
    - 武力对抗: strength >= 40（base 20 × 2.0）← 侧路

    - 暗中调查: wit >= 30（base 15 × 2.0）    ← 侧路
    （起幕没有 committed_route，所以承幕所有路线都按侧路算 ×1.5 或统一 ×2.0）
    - 保底: requirement null
  玩家当前: strength=30, money=120, wit=25
  → 金钱路线满足 ✓，其他不满足

第5步：玩家选了承幕"筹钱调解"
  → committed_route = "money"

第6步：NPC提一句"高府加派了人手，开价更狠了"

第7步：生成转幕
  prompt 注入骨架约束：
    - 武力对抗: strength >= 40（base 20 × 2.0）← 侧路
    - 金钱调解: money >= 90（base 30 × 3.0）  ← 主路！
    - 暗中调查: wit >= 30（base 15 × 2.0）    ← 侧路
    - 无保底
  玩家当前: strength=30, money=150, wit=25
  → 金钱路线满足 ✓（准备充分）

第8步：玩家选了转幕"花钱解决"
  → committed_route = "money"

第9步：生成合幕（门槛回落，善后）
第10步：玩家收尾，scaffold 清除
```

### 6.11 手段光谱与行为标签（designDoc §5.6.1）

事件选项的"手段类型"围绕已有属性/资源维度设计，每种手段策略有不同的成本结构和长期后果。

**手段维度 = 已有属性/资源维度**：

| 手段维度 | 对应属性/资源 | 典型选项描述 | 长期效果 |
|---------|-------------|-------------|---------|
| 武力 | strength | "以力服人"、威逼、护卫 | 口碑"好勇斗狠"，怯懦NPC忌惮、暴躁NPC挑战 |
| 灵巧 | agility | 潜行、偷窃、跟踪 | 口碑"神出鬼没"，被发现则信任崩塌 |
| 智谋 | wit | 调查、设计、识破 | 口碑"足智多谋"，NPC既依赖又提防 |
| 社交 | charm | 说服、安抚、调停 | 口碑"八面玲珑"，但可能被视为"老好人" |
| 金钱 | money | 贿赂、收买、悬赏 | 口碑"财大气粗"，利己NPC趋附、清高NPC反感 |
| 人情 | favor（人情债） | 借力、求助、引荐 | 口碑"善于借力"，欠人情越多风险越大 |

**与骨架路线的关系**：骨架的 3 条路线（scaffold.routes）从上述 6 个维度中选取 3 个，作为特定困境的核心考验维度。手段维度是全局池，骨架路线是困境级子集。

**行为标签与口碑传播**（复用 `rumor_system.py`）：

玩家的选择模式会被系统记录为"行为标签"，通过谣言系统在NPC之间传播，形成口碑：
- 系统统计玩家最近N次选择中各手段维度的使用频率
- 使用频率最高的1-2个维度形成行为标签（如"偏武力"、"善计谋"）
- 行为标签影响NPC的预期和反应：
  - "不择手段"的玩家 → NPC会提防他的诚实表态
  - "重情义"的玩家 → NPC更愿意主动求助
  - "财大气粗"的玩家 → NPC开价更高但也更愿意做交易

**手段与NPC性格的交互**（对接 `npc_personality.py` 7维性格）：
- 对怯懦NPC用武力 → 高效但损社会资本；对暴躁NPC用武力 → 可能激怒反噬
- 对重情NPC用金钱 → 效率低且可能被拒绝；用人情或情感投入更有效
- 对利己NPC用道德说服 → 无效；利益交换更有效但不建立忠诚

**落地方式**：手段维度不需要独立字段，因为 EventChoice.requirement 已经编码了属性维度（`PLAYER:strength:>=:45` = 武力手段）。行为标签通过统计玩家历史选择中 requirement 涉及的属性分布来自动生成，写入世界事实库。

## 7. 设计边界

### 7.1 Non-Goals

1. 不做复杂的任务链和任务依赖
2. 不做无发布人的"系统任务"
3. 不做每日签到式任务
4. 不负责数值反馈UI设计（屏幕黑影、飘字等由数值系统负责，任务系统只消费其阈值事件）
5. 不负责NPC自主行为AI（需求金字塔驱动的日程由NPC行为系统负责，任务系统只读取其需求状态来影响委托发布/接取）
6. 不负责涟漪传播计算（涟漪系统负责态度扩散和群体行为判定，任务系统只响应其输出）

### 7.2 风险与缓解

| 风险 | 缓解措施 |
|------|----------|
| 任务干扰事件节奏 | 情报委托只推送1个，不堆积 |
| 玩家不知道要去找谁 | 任务描述给出模糊提示（"问问镇上的人"） |
| 线索重复无聊 | 预设多种线索文本，AI生成变体 |
| 生存任务变成噪音 | 只在状态真正危险时触发，恢复后自动消失 |
| 势力任务太像打工 | 任务有叙事包装，可选择性拒绝 |
| 自创势力门槛太高 | 分步解锁，允许小额起步后逐步扩张 |
| 委托任务没人接 | NPC有主动接取AI，报酬合理时优先接 |
| 告示板委托太多 | 自动清理过期委托，最多显示20条 |

### 7.3 待定问题

1. **情报委托不完成怎么办？** — 倾向：不设失败，事件照样触发，玩家只是缺少准备信息
2. **多个情报委托冲突？** — 倾向：同时最多1个，新委托等旧的完成或放弃
3. **放弃委托的惩罚？** — 倾向：无惩罚，发布人好感略降（-5）
4. **退出势力？** — 倾向：可退出，损失功勋50%，势力好感度下降
5. **自创势力后想加入其他势力？** — 倾向：需先解散或与其他势力合并
6. **上司不在场？** — 倾向：上司卯时主动找玩家；睡觉则留言；上司死亡则系统分配新上司
7. **玩家睡觉时错过事件？** — 倾向：关键事件等待玩家醒来；非关键事件记录日志；紧急事件强制唤醒
8. **时间流逝速度？** — 倾向：正常1秒=1分钟；加速1秒=10分钟；暂停（菜单/对话时）
9. **取消已发布的委托？** — 倾向：可取消但手续费不退；已被接取需付违约金（报酬20%）
10. **NPC接取委托后不完成？** — 倾向：超时自动取消，委托重回告示板，NPC信誉下降
11. **委托任务与其他任务冲突？** — 倾向：不冲突，各有独立槽位限制

## 8. 开局体验流（Day 1-7）

以下用完整的7天流程展示任务系统如何驱动玩家的开局体验。每个关键节点标注了驱动它的任务类型、触发人和触发时机，对应本文档的任务体系。

```
═══════════════════════════════════════════════════
                   Day 1 · 抵达
═══════════════════════════════════════════════════

【巳时 09:00】玩家抵达城镇

  状态：HP 70，饱食度 20（饥饿警告），铜钱 5，无住所

  → 【生存任务·自动触发】饱食度 20 < 阈值 30
    任务面板显示："肚子快饿扁了，得赶紧找点吃的"
    触发人：无（系统根据状态阈值自动生成）
    消失条件：饱食度恢复到 ≥30

  城镇对你来说完全陌生：
  - 所有NPC好感=0，没人主动搭理你
  - 走到商铺前，老板面无表情看你一眼
  - 告示板上贴着几张本地事务的告示，你谁都不认识


【午时 11:00】第一个选择——怎么解决吃饭问题

  生存任务驱动玩家行动，但不指定具体方式。
  玩家通过探索城镇自然发现多种解法：

  去集市打零工（玩家卡+集市卡=打工）
    → 耗时2时辰，铜钱+15
    → 但你不认识任何商家，只能做最苦最累的活

  去城外采集（玩家卡+城外=采集）
    → 耗时1时辰，获得野果x2（每个饱食度+10）
    → 免费，但产出低，而且你不熟悉地形

  去酒馆碰运气
    → 老板娘看你灰头土脸：
      "小伙子，看你这样子是赶路来的吧。
       帮我把后院那两箱酒搬进来，管你一顿饭。"
    → 耗时1时辰，饱食度+30，老板娘好感+10
    → 饱食度≥30，【生存任务·自动消失】
    → 【设计意图】这是游戏引导玩家进入社交循环的第一个钩子
       ——帮人做事=吃饱饭+建立关系，比纯打工划算
       生存任务把玩家推出去，社交奖励把玩家拉进来


【申时 15:00】第二个压力——住处

  饱食度暂时解决了，但天色渐晚，需要找住处。

  → 【生存任务·自动触发】铜钱 5 < 阈值 30
    任务面板显示："身上没几个钱了，得想办法赚点"
    （此任务与住处压力叠加，但系统只显示一个生存任务）

  去客栈问价：
    "一晚10铜。先付后住。"
    → 如果打了工有15铜：可以住，但明天又得从0开始赚
    → 如果只有5铜：住不起

  如果之前帮了酒馆老板娘（好感10）：
    老板娘："今晚先在后院将就一宿吧，别睡大街上。"
    → 免费住一晚，寒冷值不增加
    → 【设计意图】玩家第一次切身体会到：关系=资源
       有人帮你一把，比10铜更值钱

  如果没帮老板娘：
    只能去城隍庙露宿
    → 寒冷值+15，第二天体力更差


【亥时 21:00】休息

  睡前内心独白（引出主线动机）：
  "总算活过了今天...可我不能一直这样。
   那些人迟早会找到这里，我得在这座城站稳脚跟。"

  → 【主线任务·剧情触发】"在城中站稳脚跟"
    触发人：系统（玩家内心独白）
    任务面板正式出现主线追踪
    阶段目标：找到稳定住所、建立收入来源、在城中站住脚

  → 【设计意图】主线任务不是Day 1白天出现的
    ——白天玩家忙着活命，没有余力想长远。
    只有晚上躺下来，才自然地开始想"接下来怎么办"。
    这让主线任务的出现是情感驱动的，不是系统强塞的。

Day 1 任务总结：
  ├── 【生存】饱食度<30 → 驱动玩家进城觅食 → 遇到酒馆老板娘
  ├── 【生存】铜钱<30 → 驱动玩家思考经济来源
  ├── 【主线】亥时触发"在城中站稳脚跟" → 给出长期方向
  ├── 核心教学：帮人=建立关系=获得资源（酒馆老板娘）
  └── 悬念：主线仇敌的存在被暗示


═══════════════════════════════════════════════════
                   Day 2 · 扎根
═══════════════════════════════════════════════════

【辰时 07:00】告示板刷新

  系统行为：告示板辰时更新（§3.1），新增公开委托。
  玩家昨晚的主线任务"站稳脚跟"暗示需要稳定收入
  → 自然引导玩家去告示板看机会。

  → 【公开委托·告示板接取】
    告示板上有2-3个简单委托：
    - "帮忙搬货到码头，报酬20铜" —— 发布人：赵掌柜
    - "采集草药x5，报酬15铜" —— 发布人：李大夫
    触发人：NPC（赵掌柜/李大夫各自发布）
    接取方式：玩家在告示板选择接取，无数量限制
    → 这些委托是玩家前期的主要经济来源
    → 完成委托不仅赚钱，还顺带和NPC建立好感


【巳时-午时】做委托

  完成【委托】"帮忙搬货"：
    → 耗时2时辰，铜钱+20，赵掌柜好感+10
    → 回告示板交付，赵掌柜确认完成
    赵掌柜："小伙子干活利索，以后有活再找你。"
    → 【设计意图】建立重复委托预期——NPC会持续发布新委托

  完成【委托】"采集草药"：
    → 耗时2时辰（来回城外），铜钱+15，李大夫好感+5
    → 找李大夫交付草药
    李大夫多看你一眼："你身上有伤吧？回头找我看看，老客户打个折。"
    → 【设计意图】暗示NPC关系的功能价值——好感高=服务折扣


【申时 15:00】第一次小冲突（事件，非任务）

  这是AI导演触发的随机事件，不是任务系统驱动的。
  玩家在街上走，目睹一个壮汉在欺负一个小贩：
  "上个月的摊位费还没交！今天不交别想摆了！"
  小贩求助地看向周围的人，目光扫到你。

  选项A [挺身而出]："你欺负人算什么本事？"
    requirement: PLAYER:strength:>=:15  → ❌ 不满足（当前10）
    → 选项灰显，显示"力量不足"
    → 【核心教学】玩家第一次看到"能力不够=选项被锁"
       这比任何教程都直接——"我想帮但我帮不了"

  选项B [智取]："官府的人好像刚从那边过去了..."
    requirement: PLAYER:wit:>=:12  → ❌ 不满足（当前10）
    → 也锁了

  选项C [旁观]：低头走过去
    → 无门槛，可选
    → 后果：小贩失望地看着你。壮汉得意地笑了。

  → 【设计意图】让玩家第一次产生"我要变强"的内在动机
     不是系统告诉你"请提升力量"，而是你自己想的
     "下次遇到这种事，我不想只能站着看"
  → 这个冲突不触发任何任务——它是纯叙事种子，
     让玩家内在地认可后续养成的必要性


【酉时-亥时】经济规划与休息

  今日收入：35铜（2个公开委托）
  今日支出：10铜（客栈）+ 10铜（吃饭）= 20铜
  结余：15铜
  → 铜钱累计≥30，【生存任务·自动消失】

  → 勉强维持，但没有余力发展
  → 主线任务"站稳脚跟"仍在追踪，玩家自然思考：
    怎么提高收入？怎么减少支出？
  → 这就是经营循环的自然启动——由主线任务提供方向感，
    由公开委托提供具体手段

Day 2 任务总结：
  ├── 【委托】告示板辰时刷新，接取2个 → 建立经济循环
  ├── 【主线】"站稳脚跟"持续追踪 → 提供长期方向
  ├── 【生存】铜钱≥30后消失 → 短期压力解除
  ├── 事件（非任务）：小冲突 → 种下"我要变强"的动机
  └── 经济状态：勉强维持，有提升动力


═══════════════════════════════════════════════════
                Day 3-4 · 融入
═══════════════════════════════════════════════════

  【每日辰时】告示板持续刷新新的公开委托。
  通过持续做【委托】，逐步认识城中更多NPC。
  经济逐渐稳定（每天净收入20-30铜）。

  【Day 3 关键节点——闲聊系统提供敌方信息】

  某个NPC（如酒馆老板娘，之前帮过她）好感到30时，
  玩家与她闲聊（闲聊系统，非任务），她自然透露城中势力格局：
    "最近城里不太平。前阵子来了几个外地人，
     在东街开了个铺子，价钱压得特别低。
     赵掌柜都快撑不住了...
     听说背后是什么大人物，具体我也不清楚。"

  → 【设计意图】这条信息来自闲聊系统（§3.2），不是任务触发的。
     NPC好感≥30解锁更深层对话内容，是社交系统的自然产出。
     此时不触发任何任务——敌方信息还太模糊，不足以形成行动目标。
     但这为Day 5的情报委托埋下了认知铺垫：
     等起幕事件发生时，玩家已经有了"原来是这帮人"的认知基础。

  → 赵掌柜之前帮过你（搬货委托），现在他遇到困难了
  → 还没到需要你行动的程度，但伏笔已埋下

  【Day 4 住所升级机会——主线任务阶段推进】

  如果持续与某NPC互动（如酒馆老板娘），好感到40-50时：
    "你这天天住客栈也不是个事儿。
     后院有间空屋子，虽然小了点，你要不嫌弃就搬过来吧。
     帮我每天看看店，房钱就免了。"

  → 住所升级：客栈→NPC收留（住所阶段2）
  → 每日省10铜 + 寒冷值改善
  → 【主线任务·阶段更新】"在城中站稳脚跟"推进
    ✓ 找到稳定住所 → 完成
    → 下一阶段目标浮现（具体取决于剧情发展）
  → 但你和这个NPC的命运从此绑定了——她出事，你不可能不管
  → 【设计意图】住所升级的情感重量远大于数值收益
     "有人愿意收留我"比"省了10铜"重要得多

Day 3-4 任务总结：
  ├── 【委托】持续做公开委托 → 经济稳定、社交扩展
  ├── 【主线】"站稳脚跟"阶段推进 → 住所解决
  ├── 闲聊系统（非任务）→ 获得敌方渗透的模糊信息
  ├── 社交进展：1-2个NPC好感30-50
  └── 伏笔：敌方势力的经济渗透被NPC闲聊提及


═══════════════════════════════════════════════════
              Day 5-7 · 第一个NPC人生节点 + 敌方初现
═══════════════════════════════════════════════════

  【Day 5 午时/申时】第一个NPC人生困境触发（起幕 EMERGE）

  以张铁匠为例（此时好感约20-30）：
  AI导演触发张铁匠的FateNode起幕事件——
  张铁匠的铺子被人上门施压要求搬走。

  → 这是事件系统（AI导演）触发的，不是任务系统
  → 玩家可介入（选项受当前属性约束），也可旁观
  → 关键区别在于：张铁匠是帮玩家修过武器的人，
     这个事件就不是"别人的事"，而是"我的事"：
     - 铁匠铺没了 → 我的武器谁来修？
     - 张铁匠被赶走 → 我失去一个重要的资源渠道
     - 如果张铁匠是收留我的人 → 我连住的地方都没了

  【Day 5 起幕事件余韵】→ 情报委托触发

  起幕事件结束后，余韵对话中：
    一只耳（撂狠话）："哼，等我舅舅黄三爷来了，有你好看的！"
    张铁匠拉住玩家："兄弟，黄三爷这个人...你能帮我打听打听吗？"

  → 【情报委托·当事NPC触发】"打听黄三爷的来头"
    发布人：张铁匠（FateNode当事NPC）
    触发时机：起幕事件余韵结束后（§5.5）
    任务内容：收集3条线索碎片（分散在3-5个NPC身上）
    与选项骨架的关系：3条线索分别暗示承幕的3个应对维度
      - 线索1 → "对方是练家子"（暗示 strength 路线）
      - 线索2 → "黄三爷是花钱办事的"（暗示 money 路线）
      - 线索3 → "背后似乎有人指使"（暗示 wit/调查路线）
    报酬：张铁匠好感+15，铜钱+30，以及"准备方向"本身

  → 聊天界面中出现「打探线索」快捷按钮（§5.5）
  → 玩家现在有了明确的行动目标：找NPC打听消息

  → 【设计意图】情报委托是"准备感"体验的载体（§4.3）。
     它把"下一幕可能发生什么"转化为"我现在该做什么"，
     让起幕→承幕之间的2天空白期充满有目标的探索，
     而不是漫无目的的等待。


  【Day 6】情报收集 + 敌方经济渗透可感知

  玩家执行【情报】委托，找不同NPC打探线索：
    找酒馆老板娘（好感40+）→ 点击「打探线索」
      → 老板娘是目标NPC：透露线索碎片1
      "那个黄三爷我见过，带着几个五大三粗的......"
      → 进度 1/3

    找赵掌柜（好感15+）→ 点击「打探线索」
      → 赵掌柜是目标NPC：透露线索碎片2
      "前阵子也有人来我铺子说事，丢下一锭银子让我'配合'......"
      → 进度 2/3

    找城隍庙说书人 → 点击「打探线索」
      → 非目标NPC：给出模糊背景信息，不增加进度
      "黄三爷？倒是听过这名号，不过具体的嘛......"

  与此同时，敌方势力的渗透产生可感知的玩法影响：
    - 集市上出现了敌方的低价摊位
    - 赵掌柜的【委托】报酬从20铜降到15铜（他的生意变差了）
    - 原来10铜一顿的饭开始涨价到12铜

  → 玩家不需要任何通知就能感受到：我的日常循环在变差
  → 不是"威胁度从15涨到18"这种抽象变化
  → 而是"我昨天做委托赚50铜，今天只能赚40铜了"
  → 敌方渗透同时影响了【委托】系统（报酬降低）和生存成本（物价上涨），
    让玩家的任务收益与敌方威胁直接挂钩


  【Day 7】线索汇总 + 三条线交汇 + 承幕临近

  找到第3条线索碎片后：
  → 【情报委托·完成】触发玩家内心总结
    "综合来看，黄三爷这个人......
     可以正面硬刚（但对方人多）；
     可以花钱摆平（但要筹一大笔）；
     也许可以查清幕后主使，釜底抽薪。"
  → 回复张铁匠，结算报酬（好感+15，铜钱+30）
  → 三条线索对应承幕的三条选项路线，玩家开始针对性准备

  到第7天，玩家同时面临：
  1. 【主线】"站稳脚跟"推进中，但经济环境在恶化
  2. 【情报】已完成，知道承幕（2天后）需要什么准备
  3. 【委托】报酬在下降，维持生存的成本在上升
  4. 敌方威胁：初步感知到有组织在背后搞事

  → 三条线第一次交汇在一个点上：
     "如果我不做点什么，不仅张铁匠完蛋，
      我自己也会越来越难混。"

  → 数值养成获得了切实目的：
     "我练力量不是为了解锁别人的选项，
      是因为那帮人下次来我得能打得过。"
     "我赚钱不只是为了吃饭，
      是因为将来可能需要花钱来保护我在乎的人。"

  → 玩家接下来2天的行动有了明确方向：
     根据情报线索选择准备路线（练武/攒钱/继续调查），
     用【委托】赚钱和养成，为承幕做准备。

Day 5-7 任务总结：
  ├── 【情报】Day 5起幕后触发 → Day 6-7执行 → 驱动"准备感"核心体验
  ├── 【委托】报酬受敌方渗透影响下降 → 任务系统反映世界状态变化
  ├── 【主线】持续追踪，与敌方威胁和NPC困境交织
  ├── 事件系统：起幕触发 → 余韵生成情报委托 → 形成"事件→任务→准备→事件"循环
  └── 核心循环建立：帮NPC=自保=对抗敌方=为了活下去
```

**任务系统如何驱动体验的设计要点**：

1. **任务类型的出场顺序是精心设计的**：生存任务（Day 1）→ 公开委托（Day 2）→ 主线推进（Day 4）→ 情报委托（Day 5）。每种任务在玩家最需要它的时候出现，教学负荷分散到一周内。

2. **不是所有体验都由任务驱动**：Day 1的酒馆老板娘互动、Day 2的小冲突、Day 3的闲聊获得敌方信息——这些是事件系统和社交系统的产出，不需要包装成任务。任务系统负责"给玩家明确的事做"，而非"包揽所有体验"。

3. **势力任务在Day 1-7不出现**：玩家尚未加入任何势力，没有上司给你派活。势力任务要到玩家有了一定社交基础、被势力注意到之后才会开放，这是后续阶段的内容。

4. **情报委托是"准备感"的核心载体**：Day 5起幕事件后自动产生，给玩家2天时间收集线索、针对性准备。这2天不是空白等待期，而是有目标的探索——去找谁打听、该练什么、该攒多少钱。

5. **任务系统反映世界状态**：敌方渗透不只是叙事描述，它直接影响公开委托的报酬数值（NPC生意变差→出得起的钱变少）。玩家在任务面板上就能感受到世界在变化。

## 9. 技术拆分占位

设计确认后，将拆分为以下技术文档：

| 技术文档 | 覆盖内容 |
|---------|---------|
| 任务系统技术方案 | QuestManager扩展、任务数据结构、线索收集机制、NPC闲聊扩展 |
| 势力系统技术方案 | 势力数据结构、层级关系、加入/创建/晋升、任务发布机制 |
| 委托系统技术方案 | 委托数据结构、发布/接取流程、NPC决策AI、结算逻辑 |
| 目标面板UI方案 | 面板布局、任务展示、进度追踪 |

### 实施阶段

| 阶段 | 内容 |
|------|------|
| 阶段一 | 生存任务系统：状态阈值检测、任务生成、内心独白叙事 |
| 阶段二 | 情报委托系统：数据结构、NPC发布委托、线索收集机制 |
| 阶段三 | NPC闲聊扩展：闲聊中插入线索、线索进度追踪、完成反馈 |
| 阶段四 | 目标面板UI：轻量化面板、任务展示与进度 |
| 阶段五 | 势力任务基础：层级关系、上司分配、任务发布机制 |
| 阶段六 | 势力任务完整：自创势力、功勋与晋升、任务槽位管理 |
| 阶段七 | 委托任务系统：数据结构、玩家发布委托、NPC接取AI |
| 阶段八 | 整合测试：全系统联调 |
